سیٹ اپ

npm install --legacy-peer-deps
npm run dev

--legacy-peer-deps لازمی ہے: ESLint 9 اور @eslint/js 10 متضاد پیر

پروجیکٹ کا ڈھانچہ

src/
├── api/          High-level operations (wallet-api, send, encrypt)
├── components/   React components, one panel per tab

├── i18n/         Translations and the provider

├── rpc/          JSON-RPC client
├── sdk/          Provider injected into dApps + transport
├── stealth/      Stealth address derivation
├── store/        Zustand store
├── tx/           Canonical JSON, signing, ABI helpers
├── utils/        Clipboard, progress reporting, CSV export

public/

  docs/           Static HTML documentation pages
  wasm/           Compiled PVAC module (pvac.js + pvac.wasm)

tests/unit/       Vitest
tests/e2e/        Playwright
docs/             This documentation

آرکیٹیکچر

خالص کلائنٹ سائیڈ؛ کوئی بیک اینڈ نہیں۔ ڈیٹا ایک سمت میں بہتا ہے:

React components  (src/components/)
       │  read state, dispatch actions
       ▼
Zustand store  (src/store/wallet-store.ts)
       │
       ▼
API layer  (src/api/)          ← orchestrates crypto + RPC
       │
       ├──► Crypto core  (src/crypto/)   WebCrypto, tweetnacl, @noble
       ├──► PVAC FHE     (src/pvac/)     WebAssembly
       ├──► Transaction  (src/tx/)       canonical JSON + signing
       └──► RPC client   (src/rpc/)      fetch
                                           │ HTTPS
                                           ▼
                                    Octra RPC node

ڈیزائن کی پابندیاں

Canonical JSON بائٹ کے حساب سے عین مطابق ہونا چاہیے۔ src/tx/canonical-json.ts
nlohmann::json کی کلید ترتیب اور فارمیٹنگ کو بالکل نقل کرتا ہے۔ دستخط ان ہی بائٹس پر شمار کیے جاتے ہیں، لہٰذا کسی بھی انحراف سے ایسا دستخط بنتا ہے جسے نیٹ ورک مسترد کر دیتا ہے۔ اس سیریلائزر کو "صاف" نہ کریں۔

نام رکھنا: پروڈکٹ بمقابلہ پروٹوکول۔ "Orion Wallet" پروڈکٹ ہے۔ octra_* RPC طریقے،
oct ایڈریس پریفکس، OCT ٹکر، اور "Octra Network" پروٹوکول شناخت کار ہیں
اور انہیں کبھی تبدیل نہیں کرنا چاہیے۔

بلڈ سسٹم

TypeScript کنفیگ فائلیں سچائی کا واحد ذریعہ ہیں:

  • vite.config.ts
  • vitest.config.ts
  • playwright.config.ts
ان کے لیے .js ہم منصب شامل نہ کریں۔ Vite vite.config.js کو
vite.config.ts سے پہلے حل کرتا ہے، لہٰذا ایک پرانی ٹرانسپائلڈ نقل خاموشی سے اصلی کنفیگ پر حاوی ہو جاتی ہے اور .ts فائل میں کی گئی ترامیم کا کوئی اثر نہیں ہوتا۔ وہ تین فائل نام .gitignore میں ہیں۔
eslint.config.js حقیقی فلیٹ کنفیگ ہے اور جان بوجھ کر رکھی گئی ہے۔

انہیں نظر انداز کرنا اکیلا کافی نہیں تھا، کیونکہ کسی چیز نے انہیں بننے سے نہیں روکا:
tsconfig.node.json ایک composite پروجیکٹ ہے، جو declaration emit پر مجبور کرتا ہے، اور بغیر
outDir کے کوئی بھی tsc -b vite.config.js کو سورس کے بالکل ساتھ لکھ دیتا تھا۔ یہ دو بار ہوا۔
اس پروجیکٹ کے لیے emit اب node_modules/.tmp/tsconfig-node/ میں جاتا ہے، جہاں یہ کسی چیز پر حاوی
نہیں ہو سکتا۔ اگر آپ اس پروجیکٹ میں کوئی کنفیگ فائل شامل کریں تو outDir کو نہ چھیڑیں۔

ماحولیاتی فلیگز

فلیگاثر
VITE_ALLOW_HTTP_ENDPOINTS=1بلڈ وقت پر connect-src CSP ڈائریکٹیو میں http: جوڑتا ہے، تاکہ سیلف ہوسٹڈ بلڈ سادہ-http RPC نوڈ تک پہنچ سکے۔ ہر اوریجن کی صارف رضامندی اب بھی لاگو ہوتی ہے — دیکھیں src/wallet/endpoint-policy.ts

صرف بلڈ وقت پر مرتب کیا جاتا ہے۔ اسے vite.config.ts میں allowHttpEndpointsCsp پلگ ان پڑھتا ہے
اور index.html کو دوبارہ لکھتا ہے؛ اس کا کوئی رن ٹائم اثر نہیں، کیونکہ میٹا-ٹیگ CSP کو دستاویز پارس ہونے کے بعد وسیع نہیں کیا جا سکتا۔

ہیڈرز

COOP/COEP کو same-origin / require-corp پر سیٹ کیا گیا ہے (مستقبل کے WASM threading کے لیے محفوظ)،
ساتھ /connect پر unsafe-none اوور رائڈز تاکہ پاپ اپ کا postMessage + MessagePort
منتقلی کام کرے۔ ڈیو ہیڈرز vite.config.ts میں رہتے ہیں؛ پروڈکشن ہیڈرز vercel.json میں۔
دونوں کو ہم آہنگ رکھیں۔

Content-Security-Policy

index.html میں بیان کردہ۔ script-src میں 'wasm-unsafe-eval' شامل ہونا چاہیے — Chromium اس کے بغیر
WebAssembly.instantiate() سے انکار کرتا ہے، اور یہی وہ چیز تھی جس نے PVAC ماڈیول کو خاموشی سے لوڈ ہونے سے روکا۔ وہ ڈائریکٹیو صرف WebAssembly کمپائلیشن کی اجازت دیتی ہے؛ یہ JavaScript eval() کو دوبارہ فعال نہیں کرتی۔

connect-src ہے 'self' https: علاوہ loopback (http://localhost:*، http://127.0.0.1:*،
http://[::1]:*) تاکہ مقامی طور پر چلنے والا نوڈ عام طور پر صاف متن کھولے بغیر کام کرے۔ http:// پر کوئی بھی اور چیز src/wallet/endpoint-policy.ts کے ذریعے گیتڈ ہے، جو فیصلہ کرنے والی واحد جگہ ہے — URL علاوہ ایک واضح سیاق کا خالص فنکشن، تاکہ اسٹور، Settings UI اور ٹیسٹ آپس میں متفق نہ ہو سکیں۔ اور کہیں بھی ایڈہاک URL جانچیں شامل نہ کریں۔ تین آزاد رکاوٹیں لاگو ہوتی ہیں (mixed content → CSP → صارف کی رضامندی) اور فیصلہ سب سے بنیادی رکاوٹ کو پہلے رپورٹ کرتا ہے، تاکہ صارف سے کبھی یہ نہ کہا جائے کہ allowlist ٹھیک کرو جب براؤزر خود انکار کر رہا ہو۔

PVAC WASM پائپ لائن

بنانا

git clone https://github.com/emscripten-core/emsdk.git /tmp/emsdk
cd /tmp/emsdk && ./emsdk install latest && ./emsdk activate latest
source /tmp/emsdk/emsdk_env.sh

git clone https://github.com/octra-labs/webcli ../webcli-source
python3 scripts/patch-pvac-aes.py ../webcli-source/pvac   # software AES fallback
npm run build:wasm

patch-pvac-aes.py اس لیے درکار ہے کیونکہ PVAC ہارڈویئر AES (AES-NI یا
ARM کرپٹو ایکسٹینشنز) کے بغیر سختی سے #error کرتا ہے، جو WebAssembly پیش نہیں کرتا۔ پیچ ایک پورٹیبل
سافٹ ویئر نفاذ شامل کرتا ہے جو بائٹ کے حساب سے ایک جیسا ہے لیکن تقریباً 5–10 گنا سست ہے۔ یہ اضافی ہے: ہارڈویئر
پاتھ اچھوتے رہتے ہیں، اور ایک بیک اپ .hpp.bak لکھا جاتا ہے۔

لوڈ کرنا

src/pvac/wasm-bridge.ts ماڈیول کو تین مراحل میں لوڈ کرتا ہے:

  1. Probe — گلو URL پر HEAD، تاکہ "built نہیں" (404) کو
    "CSP نے روکا" سے ممتاز کیا جا سکے۔ اس کے بغیر دونوں ایک جیسی مبہم امپورٹ ناکامی کی طرح سطح پر آتے ہیں۔
  2. Import — /* @vite-ignore */ والے مطلق URL کا ڈائنامک import()۔ یہ
    مطلق ہونا چاہیے: ننگا اسپیسیفائر حل نہیں ہوتا، اور ./wasm/pvac.js /assets/ کے مقابلے میں حل ہو کر 404 دیتا ہے۔
  3. Verify — برج کو تبدیل کرنے سے پہلے تمام 13 مطلوبہ _pvac_* ایکسپورٹس کے موجود ہونے کی تصدیق کریں۔

پہلے کی بلڈز سیریلائزیشن فنکشنز کو چھوڑ دیتی تھیں، جس سے encrypt/decrypt اس طرح ٹوٹتا تھا
جیسے نوڈ صرف "malformed transaction" رپورٹ کرتا۔

ناکامیاں PvacFailureReason کے طور پر درجہ بند ہوتی ہیں: not-built، csp-blocked،
missing-exports، init-failed، unknown۔ ہر ایک Settings میں دکھائے گئے کسی ٹھوس علاج سے جڑتا ہے۔ ناکامی پر سنگلٹن پرامس ری سیٹ ہوتا ہے تاکہ ↻ Reload PVAC کیشڈ مسترد کو دوبارہ چلانے کے بجائے دوبارہ کوشش کر سکے۔

میموری کے اصول

C API دستی-میموری ہے۔ ہر _malloc کو ایک _free چاہیے؛ ہر serialize_* ایک بفر لوٹاتا ہے
جسے _pvac_free_bytes سے جاری کرنا ضروری ہے۔ keygen/enc_* سے ملنے والے ہینڈلز کو ان کا
مماثل _pvac_free_* چاہیے۔ try/finally استعمال کریں — پیٹرن کے لیے WasmPvacBridge دیکھیں۔

Zustand، src/store/wallet-store.ts میں۔ یہ والیٹ، RPC کلائنٹ، ترتیبات، PVAC
اسٹیٹس، ٹوسٹس، اور عالمی لوڈنگ فلیگ کا مالک ہے۔

عالمی لوڈنگ فلیگ (isLoading) پوری اسکرین کے بلر اوورلے کو چلاتا ہے اور صرف
پورے ایپ ٹرانزیشنز کے لیے مخصوص ہے، جیسے والیٹ ان لاک۔ فی پینل والے کام کو
اس کی بجائے usePanelLoading استعمال کرنا چاہیے — نیچے دیکھیں۔

غلطیوں کا انتظام

src/components/ErrorBoundary.tsx Layout.tsx میں ہر پینل کو لپیٹتا ہے، فعال ٹیب کے حساب سے کلید شدہ تاکہ ٹرپ شدہ باؤنڈری نیویگیشن پر ری سیٹ ہو، علاوہ main.tsx میں روٹ پر ایک باؤنڈری۔

یہ ظاہر سے زیادہ اہم ہے۔ index.html میں یہ ہے:

#root:empty::before { content: 'Loading Orion Wallet…'; }

باؤنڈری کے بغیر، رینڈر وقت کی کوئی بھی تھرو React 18 کو پورا ٹری ان ماؤنٹ کرنے پر مجبور کرتی ہے، #root
خالی ہو جاتا ہے، اور وہ فالبیک رینڈر ہوتا ہے — ایک خالی سفید صفحہ بنتا ہے جو ہمیشہ کے لیے لوڈنگ میں اٹکا نظر آتا ہے۔ باؤنڈری شیل کو زندہ رکھتی ہے اور دوبارہ قابلِ کوشش ایرر کارڈ دکھاتی ہے۔

نتیجہ: رینڈر کے دوران بلائے جانے والے فنکشنز کو خراب ان پٹ پر نہیں پھینکنا چاہیے۔
src/tx/builder.ts میں formatAmount unknown قبول کرتا ہے اور پلیس ہولڈر تک گھٹ جاتا ہے،
کیونکہ نہ RPC جوابات اور نہ لوکل tx کیش سکیما-تصدیق شدہ ہیں۔ رینڈر کرنے سے پہلے ناقابلِ بھروسہ قطاروں کو نارملائز کریں — HistoryView پیٹرن دکھاتا ہے۔

لوڈنگ اسٹیٹس

پینل کے دائرے والے کام کے لیے usePanelLoading (src/hooks/usePanelLoading.ts) استعمال کریں:

const panelLoading = usePanelLoading();

await panelLoading.run('Loading history', async () => {
  const data = await fetchSomething();
  if (!panelLoading.isMounted()) return;   // guard late setState
  setData(data);
}, 'Fetching from the network…');

پھر رینڈر کریں <ProcessingModal open={panelLoading.loading} … dismissible onClose={panelLoading.hide} />۔

دو خصوصیات اہم ہیں: موڈل dismissible ہے (کام پس منظر میں جاری رہتا ہے، لہٰذا ایک سست
نیٹ ورک صارف کو کبھی نہیں پھنساتا)، اور اسٹیٹ رائٹس isMounted() پر گیتڈ ہیں تاکہ
درمیانِ پرواز نیویگیٹ کرنے سے کوئی موڈل اسکرین پر اٹکا نہ رہے۔

اسٹوریج اور مائیگریشنز

IndexedDB بذریعہ idb، ڈیٹابیس orion-wallet، ورژن 6۔ اسٹورز ایک بار src/wallet/storage.ts میں OBJECT_STORES ارے میں اعلان کیے جاتے ہیں؛ نئے وہیں شامل کریں تاکہ تخلیق اور مائیگریشن مستقل رہیں — وہ ارے wipeEverything() کو بھی چلاتا ہے، لہٰذا کہیں اور شامل کیا گیا اسٹور وائپ سے بچ جاتا۔

مائیگریشنز صرف اضافی ہیں: DB_VERSION بڑھائیں، ارے میں append کریں، اور نئے اندراجات کے پاس کمنٹ میں ورژن نوٹ کریں۔ موجودہ اسٹورز کبھی تبدیل نام یا حذف نہیں ہوتے۔
اب تک کے ورژن: v2 SDK اسٹورز، v3 OCS01 ٹوکنز، v4 oct:// بک مارکس، v5
unlock-session-keys، v6 contacts + passkey-unlock۔

ری برانڈ مائیگریشن

ڈیٹابیس کا نام webcli-react سے بدلنا ہر موجودہ والیٹ کو یتیم کر دیتا، کیونکہ
IndexedDB ڈیٹا کو ڈیٹابیس نام سے اسکوپ کرتا ہے۔ migrateLegacyDatabase پہلی لانچ پر تمام اسٹورز کو آگے نقل کرتا ہے۔ یہ ہے:

  • idempotent — ہدف میں کوئی والیٹ آتے ہی چھوڑ دیا جاتا ہے
  • غیر تباہ کن — لیگیسی ڈیٹابیس رول بیک کے لیے برقرار رہتا ہے
  • غیر مہلک — ناکامیاں لاگ ہوتی ہیں، کبھی نہیں پھینکی جاتیں؛ مائیگریشن بگ کو اسٹارٹ اپ نہیں روکنا چاہیے

یاد رکھیں کہ E2E ہیلپرز میں clearIndexedDB کو دونوں ڈیٹابیسز حذف کرنے چاہئیں، ورنہ
مائیگریشن لیگیسی ڈیٹا کو سیدھا واپس نقل کر دیتی ہے اور "صاف حالت" صاف نہیں ہوتی۔

واضح طور پر Orion Wallet کو ہدف بنانا چاہتے ہیں؛ عام wallet_* نام معاون رہتے ہیں تاکہ
موجودہ انٹیگریشنز کام کرتی رہیں۔

src/sdk/protocol.ts میں canonicalizeMethod dispatch سے پہلے ہر طریقہ کار کا نام اپنی canonical
wallet_* شکل تک گھٹاتا ہے، لہٰذا دونوں نام اسپیسز کبھی بھی ہم آہنگی سے باہر نہیں جا سکتے۔

کنکشن لائف سائیکل

ہینڈ شیک (ہر سیشن میں ایک بار):

  1. dApp provider.connect() کال کرتا ہے → PopupTransport /connect?v=1&rid=…&origin=… کھولتا ہے
  2. والیٹ ConnectApp رینڈر کرتا ہے، ضرورت ہو تو صارف ان لاک کرتا ہے
  3. والیٹ window.postMessage پر hello + MessagePort بھیجتا ہے، origin-تصدیق شدہ
  4. dApp پورٹ پر challenge کا جواب بھیجتا ہے (اینٹی ری پلے)
  5. ConnectHandler ack کی تصدیق کرتا ہے، CONNECT RPC پیش کرتا ہے → ایڈریس، اکاؤنٹس، نیٹ ورک لوٹاتا ہے

کنیکٹ کے بعد:

  • پاپ اپ بند ہو سکتا ہے، لیکن MessagePort کھلا رہتا ہے — یہ ونڈو سے آزاد ہے
  • سیشن IndexedDB (sdk-sessions) میں idle + absolute TTL کے ساتھ قائم رہتا ہے
  • پڑھنے والے طریقے (getBalance، getAccounts) سیشن کے لیے خاموش ہیں
  • دستخطی طریقے ہمیشہ ایک نئی منظوری پرامپٹ کھولتے ہیں

"کنیکٹ کام کرتا ہے، باقی کچھ نہیں" کا حل:

اصل میں PopupTransport.isConnected() popup.closed چیک کرتا تھا، لہٰذا منظوری ونڈو بند ہونے کے بعد ہر کال "Transport is not connected" سے ناکام ہوتی تھی۔ اب یہ صرف پورٹ چیک کرتا ہے، جو پاپ اپ سے زیادہ دیر زندہ رہتا ہے۔ والیٹ منظوری کے بعد پاپ اپ بند کر دیتا ہے، لیکن کنکشن زندہ رہتا ہے۔

اجازت کا ماڈل

کنیکٹ کے وقت: صرف پڑھنے والے اسکوپس (viewAccounts، viewBalance، viewNetwork)۔

دستخطی اسکوپس (signMessage، signContract، وغیرہ) پہلی کامیاب
منظوری پر سستی سے دیے جاتے ہیں۔ اس اصلاح سے پہلے، وہ DEFAULT_PERMISSIONS میں غائب تھے اور ڈسپیچر پرامپٹ ظاہر ہونے سے پہلے ہر دستخطی کال کو UNAUTHORIZED سے مسترد کر دیتا تھا —
علامت کی دوسری جڑ وجہ۔

اب:

  • اجازت کی جانچ غیر عطا کردہ دستخطی اسکوپس کو منظوری پرامپٹ تک جانے دیتی ہے
  • منظوری پر، grantPermission اسکوپ کو سیشن میں محفوظ کرتا ہے
  • بعد کی کالیں اجازت کی جانچ چھوڑ دیتی ہیں لیکن پھر بھی منظوری چاہتی ہیں — اسکوپ دینا صرف یہ ریکارڈ کرتا ہے کہ صارف اس بات سے متفق ہے کہ dApp پوچھ سکتا ہے

منسوخی واضح ہے: revokePermission اسکوپ کو permissions سے ہٹاتا ہے اور اسے
deniedPermissions میں ریکارڈ کرتا ہے، جسے ڈسپیچر یکسر مسترد کرتا ہے۔

سیکیورٹی انویریئنٹس

انہیں کمزور نہ کریں:

  • Origin validation ہر آنے والے postMessage پر (PopupTransport.ts، rpc-handler.ts)
  • Anti-replay: CSPRNG چیلنج + dApp نانس + فی سیشن مونوٹونک نانس۔ makeId صرف پیغام کی ارتباط کے لیے ہے اور اسے کبھی بھی سیکیورٹی قدر کے طور پر استعمال نہیں کرنا چاہیے
  • اجازتیں فی اوریجن ہیں، sdk-sessions میں محفوظ، اور واضح طور پر دی اور واپس لی جاتی ہیں
  • MessagePort آزادی: پورٹ پاپ اپ سے زیادہ زندہ رہتا ہے۔ منتقلی کے بعد، والیٹ منظوری ونڈو کو کنکشن توڑے بغیر بند کر سکتا ہے
  • ممنوعہ طریقے کلائنٹ سائیڈ (WalletProvider) اور والیٹ سائیڈ دونوں پر مسترد کیے جاتے ہیں
    (rpc-handler)، تاکہ ٹرانزیکشن عمل کبھی بھی نچلی سطح کے request() escape hatch کے ذریعے SDK تک نہ بھاگ سکے
  • localStorage میں صرف سیشن بحالی کا اشارہ (ایڈریس، نیٹ ورک) ہوتا ہے — کبھی راز نہیں

dApp انٹیگریشن

فوری آغاز

import { WalletProvider } from '@orion-wallet/sdk';

const provider = new WalletProvider({
  walletUrl: 'https://orionwallet.example/connect',
  capabilities: [
    'signMessage',
    'signTypedData',
    'approveContract',
    'signContract',
    'multiAccount',
    'events',
    'sessionRestore',
    'customNetworks',
  ],
});

const result = await provider.connect();

سیشن مینجمنٹ

Orion سیشنز 30 منٹ بے عملی یا 8 گھنٹے مطلق کے بعد ختم ہوتے ہیں۔ SDK بلٹ ان سیشن ہیلتھ چیکس اور آٹو ریکنیکٹ فراہم کرتا ہے:

// Check session health before every signing operation
if (!provider.isSessionAlive()) {
  await provider.refreshSession();
}

// Listen for session expiry events
provider.on('sessionExpired', () => {
  setConnected(false);
});

نیٹ ورکس، بشمول صارف کے اپنے

ایک صارف Settings → Network میں اپنا نیٹ ورک شامل کر سکتا ہے (ان کا اپنا نوڈ، ڈیو نیٹ فورک، ایک
ادا شدہ RPC)۔ وہ نیٹ ورک فرسٹ کلاس ہیں: وہ کنیکٹ پاپ اپ کے سلیکٹر میں
پیش سیٹس کے ساتھ ظاہر ہوتے ہیں، اور ایک منسلک dApp انہیں دیکھ سکتا ہے۔

// Which network am I on? A record, not just an id string.
const active = await provider.getNetworkInfo();
// { id: 'home-node', name: 'Home node', explorerUrl: 'https://octrascan.io',
//   icon: '🏠', custom: true }

// Everything the wallet offers — presets first, user-added ones after.
const all = await provider.getNetworks();
const userAdded = all.filter((n) => n.custom);

// Cached from the connect reply, no round-trip; null before connect.
provider.networkInfo();

provider.on('networkChanged', ({ network, chainId, networkInfo }) => {
  // networkInfo is present on wallets that granted `customNetworks`.
  setChain(networkInfo?.name ?? network);
});

ان میں سے کسی پر بھی بھروسہ کرنے سے پہلے customNetworks کی صلاحیت پر فیچر-ڈیٹیکٹ کریں — پرانی
والیٹ بلڈز صرف ننگے wallet_getNetwork کا جواب دیتی ہیں، جو id سٹرنگ لوٹاتا ہے۔

NetworkInfo جان بوجھ کر کوئی rpcUrl اور کوئی relayerUrl نہیں رکھتا۔ صارف کا شامل کردہ
نیٹ ورک اکثر نجی اینڈ پوائنٹ ہوتا ہے — LAN ایڈریس، ٹنل، یا API کلید کوئری سٹرنگ میں رکھنے والا پرووائیڈر URL — اور اسے ہر اس سائٹ کو دینا جس سے صارف منسلک ہوتا ہے، ان کا انفراسٹرکچر لیک کر دے گا۔ dApp کو اس کی ضرورت نہیں: ہر پڑھائی والیٹ کے ذریعے جاتی ہے
(wallet_getBalance اور دیگر) اور عمل کبھی بھی والیٹ UI سے باہر نہیں جاتا۔ وائر پر جو جاتا ہے وہی ہے جو dApp کو جائز طور پر چاہیے — یہ کس نیٹ ورک سے بات کر رہا ہے، آیا مالک نے اسے ہاتھ سے شامل کیا (custom)، اور ٹرانزیکشن کہاں لنک کرنی ہے (explorerUrl)۔

کوئی wallet_switchNetwork نہیں ہے۔ سوئچنگ والیٹ کی اپنی UI میں رہتی ہے — پاپ اپ کا
سلیکٹر یا مین ونڈو کا network pill — اس اصول کے مطابق کہ اسٹیٹ تبدیلیاں کبھی dApp سے شروع نہیں ہوتیں۔ ایک dApp جسے دوسرے نیٹ ورک کی ضرورت ہو وہ صارف سے سوئچ کرنے کو کہتا ہے، پھر networkChanged کا انتظار کرتا ہے۔

networkChanged ان دونوں جگہوں سے خارج ہوتا ہے جہاں سوئچ ہو سکتا ہے: کنیکٹ پاپ اپ اور
مین ونڈو۔ سیشن پاپ اپ بند ہونے پر مین ونڈو کو سونپے جاتے ہیں، لہٰذا جب تک زیادہ تر صارف network pill چھوتے ہیں پاپ اپ کافی پہلے جا چکا ہوتا ہے — Layout.tsx اپنائے گئے ہینڈلرز کو خارج کرتا ہے تاکہ منسلک dApp پرانا نیٹ ورک دکھاتا ہوا نہ رہ جائے۔

دو آزاد کلاسیں WalletHost کو لاگو کرتی ہیں — src/connect/host.ts (مین ونڈو) اور ایک
ان لائن ہوسٹ src/connect/ConnectApp.tsx (پاپ اپ) میں۔ انٹرفیس میں شامل کی گئی کوئی بھی چیز دونوں میں لاگو ہونی چاہیے، علاوہ tests/unit/connect-handler.test.ts میں فکسچر۔

ممنوعہ طریقے

SDK ان طریقوں کو ٹرانسپورٹ تک پہنچنے سے پہلے مقامی طور پر روکتا ہے۔ والیٹ بھی دوبارہ چیک کرتا ہے، تاکہ ٹرانزیکشن عمل کبھی بھی فرار نہ ہو سکے:

  • wallet_sendTransaction / sendTransaction
  • wallet_broadcastTransaction / broadcastTransaction
  • wallet_transfer / transfer
  • wallet_swap / swap
  • wallet_bridge / bridge

سیشن مینجمنٹ

Orion Wallet سیشنز SDK کے ذریعے خود بخود منظم ہوتے ہیں۔ سیشنز اس کے بعد ختم ہوتے ہیں:

  • Idle timeout: 30 منٹ کی بے عملی
  • Absolute timeout: کنکشن سے 8 گھنٹے

dApp کسی بھی وقت سیشن کی صحت چیک کر سکتا ہے:

if (!provider.isSessionAlive()) {
  await provider.refreshSession();
}

جب سیشن ختم ہوتا ہے تو والیٹ ایک sessionExpired واقعہ خارج کرتا ہے۔ dApp کو اس واقعہ کو سننا چاہیے اور صارف سے دوبارہ منسلک ہونے کو کہنا چاہیے:

provider.on('sessionExpired', () => {
  // Prompt user to reconnect
  setConnected(false);
});

سیشن بحالی خود بخود ہوتی ہے — والیٹ سیشن کا اشارہ IndexedDB میں محفوظ رکھتا ہے، لہٰذا میعاد ختم ہونے کے بعد دوبارہ منسلک ہونے کے لیے صارف کو اپنا والیٹ دوبارہ درآمد کرنے کی ضرورت نہیں۔

E2E نوٹ: Playwright کی ناکامیوں کی دیوار پر یقین کرنے سے پہلے، مشین چیک کریں، diff نہیں۔
دو ماحولیاتی حدود ایسی ناکامیاں پیدا کرتی ہیں جو بالکل حقیقی ریگریشنز لگتی ہیں:

  • عارضی جگہ۔ Chromium ہر براؤزر پروفائل TMPDIR (/tmp بطور ڈیفالٹ) کے تحت رکھتا ہے۔ اگر
    وہ فائل سسٹم بھرا ہو — آسان جب /tmp دوسرے عملوں کے ساتھ شیئر شدہ چھوٹی tmpfs ہو —
    کونٹیکسٹ لانچ پر مر جاتے ہیں اور غیر متعلقہ ٹیسٹ ملی سیکنڈز میں ناکام ہوتے ہیں، یا 30 سیکنڈ کے
    ٹائم آؤٹ تک لٹکتے ہیں۔ پہلے df -h /tmp؛ کسی کشادہ فائل سسٹم پر TMPDIR=$HOME/.cache/e2e-tmp کے ساتھ دوبارہ چلائیں اور وہی سپیکس ٹائم آؤٹ سے گزر کر ~4 سیکنڈ میں پاس ہو جاتی ہیں۔
  • میموری۔ فی ورکر تقریباً 2 GB خالی میموری۔ جب یہ ختم ہو جائے تو Chromium ٹیسٹ کے
    درمیان مارا جاتا ہے اور Playwright Target crashed رپورٹ کرتا ہے؛ --workers=1 کے ساتھ دوبارہ چلائیں۔

بگ ٹھیک کرتے وقت، صرف اصلاح نہیں، ناکامی کے موڈ کو دستاویز کرنے والا ٹیسٹ شامل کریں۔
tests/unit/history-view.test.ts اور error-boundary.test.tsx اسی پر عمل کرتے ہیں: ہر ایک اس علامت کا نام لیتا ہے جسے وہ دوبارہ رونما ہونے سے روکتا ہے۔
