آغاز کرنا

تقاضے

  • Chrome، Edge، Firefox، یا Safari کا کوئی موجودہ ورژن
  • JavaScript فعال ہو
  • اگر آپ خفیہ کردہ بیلنس کی خصوصیات استعمال کرنے کا ارادہ رکھتے ہیں تو تقریباً 4 GB RAM

اسے چلانا

کوئی ہوسٹ شدہ ڈیپلائمنٹ استعمال کریں، یا اسے مقامی طور پر چلائیں:

npm install --legacy-peer-deps
npm run dev

پھر <http://localhost:5173> کھولیں۔

والیٹ بنانا

  1. Create New Wallet منتخب کریں، اکاؤنٹ کا نام رکھیں، اور ایک PIN منتخب کریں۔ یہ PIN اس آلے پر والیٹ کو خفیہ کرتا ہے۔
  2. اپنا ریکوری فقرہ لکھ لیں۔ آپ کو 12 الفاظ دکھائے جاتے ہیں۔ انہیں دیے گئے بالکل اسی ترتیب میں کاغذ پر نقل کریں۔
  3. I've Written It Down منتخب کریں۔ اس کے بعد والیٹ آپ سے تصادفی طور پر منتخب کردہ 3 الفاظ دوبارہ ٹائپ کرنے کو کہتا ہے، تاکہ یہ ثابت ہو کہ فقرہ واقعی اسکرین سے ہٹ چکا ہے۔ Show Phrase Again
    اگر آپ کو دوبارہ دیکھنے کی ضرورت ہو تو اسے واپس لے آتا ہے؛ غلط جواب آپ کو صرف دوبارہ کوشش کرنے دیتا ہے۔
  4. جب الفاظ درست ثابت ہو جاتے ہیں، تو والیٹ کھل جاتا ہے۔
والیٹ بنانا اسے کھولتا نہیں — لفظی جانچ پاس کرنا کھولتا ہے۔ اس وقت تک آپ
اب بھی چھوڑ کر جا سکتے ہیں، اور کچھ ضائع نہیں ہوتا، کیونکہ فقرے پر ابھی تک انحصار نہیں کیا گیا۔
آپ کا ریکوری فقرہ آپ کے والیٹ کو بحال کرنے کا واحد طریقہ ہے۔ جس کے پاس بھی یہ ہو
وہ آپ کے فنڈز کو کنٹرول کرتا ہے۔ اسے آف لائن محفوظ کریں۔ اسے کبھی تصویر نہ بنائیں، کسی ویب سائٹ میں ٹائپ نہ کریں،
یا کسی چیٹ یا ای میل میں پیسٹ نہ کریں۔

PIN بمقابلہ ریکوری فقرہ

ریکوری فقرہPIN
مقصدکہیں بھی آپ کا والیٹ بحال کرتا ہےصرف اسی آلے پر اسے ان لاک کرتا ہے
اگر گم ہو جائےفنڈز ناقابلِ بازیافت ہیںریکوری فقرے سے بحال کریں
کہاں محفوظ ہوتا ہےآف لائن، آپ کے ذریعےکبھی محفوظ نہیں ہوتا — صرف آپ کو معلوم ہوتا ہے

موجودہ والیٹ درآمد کرنا

Import منتخب کریں اور ان میں سے ایک چنیں:

  • ریکوری فقرہ — اپنے 12/24 الفاظ درج کریں
  • نجی کلید — ایک base64 نجی کلید پیسٹ کریں
  • والیٹ فائل — ایک خفیہ کردہ .oct فائل اپ لوڈ کریں اور اس کا PIN درج کریں

روزمرہ استعمال

اپنا بیلنس چیک کرنا

Balance ٹیب آپ کا عوامی بیلنس دکھاتا ہے اور، اگر PVAC فعال ہو، تو آپ کا خفیہ کردہ بیلنس۔

وصول کرنا

اپنا پتہ اور ایک QR کوڈ دکھانے کے لیے Receive کھولیں۔ آپ کا پتہ عوامی ہے اور
شیئر کرنا محفوظ ہے۔

آپ ایک مخصوص رقم کی درخواست بھی کر سکتے ہیں۔ اس صورت میں QR کوڈ رقم کو پتے کے
ساتھ لے جاتا ہے (بطور octra:<address>?amount=<OCT>)، تاکہ اسے اسکین کرنے والا والیٹ دونوں کو پہلے سے بھر دے۔
اگر کوئی رقم درخواست نہ کی جائے، تو کوڈ صرف ایک سادہ پتہ رہتا ہے، جسے کوئی بھی اسکینر پڑھ سکتا ہے۔

رقم بھیجنا

  1. Send کھولیں۔
  2. وصول کنندہ کو کسی بھی طریقے سے دیں جو آپ کو مناسب لگے:
    • پتہ پیسٹ کریں (یہ oct سے شروع ہوتا ہے)۔
    • 📇 Contacts… سے کوئی محفوظ شدہ نام منتخب کریں۔
    • اپنے کیمرے سے QR کوڈ پڑھنے کے لیے 📷 Scan منتخب کریں۔ براؤزر پہلی بار کیمرے کی اجازت مانگتا ہے؛ تصویر صفحے ہی میں پروسیس ہوتی ہے اور کبھی اپ لوڈ نہیں ہوتی۔ اگر کوڈ کے ساتھ رقم بھی ہو تو اسکین کرنے سے وہ رقم بھی بھر جاتی ہے۔
  3. ایک رقم درج کریں۔
  4. فیس اور نانس (nonce) کا جائزہ لیں، پھر اپنے PIN سے تصدیق کریں۔

جب پتہ کسی محفوظ شدہ رابطے سے ملتا ہے تو فارم اس کے آگے نام دکھاتا ہے — ایک نام جو آپ
پہچانتے ہیں، base58 کی لمبی سٹرنگ سے کہیں بہتر جانچ ہے۔ نئے پتے کے لیے، ＋ Save to contacts اسے آپ کی منتخب کردہ لیبل کے تحت محفوظ کرتا ہے، تاکہ اگلی ادائیگی پیسٹ کرنے کے بجائے صرف ایک انتخاب ہو۔

تصدیق سے پہلے ہمیشہ وصول کنندہ کے پتے کے پہلے اور آخری حروف دیکھ لیں۔
ٹرانزیکشنز کو واپس نہیں کیا جا سکتا۔

ہسٹری

History حالیہ ٹرانزیکشنز کی فہرست دکھاتا ہے۔ جب نیٹ ورک ناقابلِ رسائی ہو تو کیشڈ اندراجات
دکھائے جاتے ہیں اور ⚠ Cached سے نشان زد ہوتے ہیں۔

⤓ ٹیبل کو CSV فائل میں ایکسپورٹ کرتا ہے (وقت، ہیش، قسم، از، بجانب، سمت، رقم، فیس،
اسٹیٹس) اسپریڈشیٹ یا آپ کے اپنے ریکارڈ کے لیے۔ یہ اس وقت لوڈ کی گئی قطاروں کو ایکسپورٹ کرتا ہے —
جو آپ دیکھتے ہیں وہی ملتا ہے — لہٰذا اگر آپ لمبی رینج چاہتے ہیں تو پہلے Load more استعمال کریں۔
فائل آپ کا براؤزر آپ کے ڈاؤن لوڈ فولڈر میں لکھتا ہے؛ کہیں بھی کچھ نہیں بھیجا جاتا۔

رابطے (ایڈریس بک)

Settings → 📇 Contacts ان ناموں کے تحت پتوں کی فہرست رکھتا ہے جو آپ منتخب کرتے ہیں۔ ہر اندراج میں
ایک پتہ، ایک نام، اور ایک اختیاری نوٹ ہوتا ہے — "میمو ضروری ہے" یا یہ کہ ڈپازٹ پتہ کس ایکسچینج کا ہے، لکھنے کے لیے اچھی جگہ۔

کیوں زحمت کریں: جس پتے کو آپ پڑھ نہیں سکتے، وہ پتہ ہے جسے آپ جانچ نہیں سکتے۔ ایک بار وصول کنندہ محفوظ ہو جائے،
Send فارم انہیں نام سے پیش کرتا ہے اور جب آپ پتہ دوبارہ پیسٹ کرتے ہیں تو اس پر لیبل لگا دیتا ہے، تاکہ
بدلا یا کٹا ہوا پتہ نمایاں ہو جائے بجائے اس کے کہ گھل مل جائے۔

  • یہاں Add کریں، یا Send فارم سے براہِ راست ＋ Save to contacts استعمال کریں۔
  • ✎ اندراج کا نام تبدیل کرتا ہے، 🗑 اسے ہٹاتا ہے۔ رابطہ ہٹانے کا چین پر کوئی اثر نہیں ہوتا۔
  • ⤓ فہرست کو CSV میں ایکسپورٹ کرتا ہے، تاکہ اسے آپ کے دیگر ریکارڈ کے ساتھ رکھا جا سکے یا
    کسی اور براؤزر میں منتقل کیا جا سکے۔

رابطے صرف اس براؤزر میں رہتے ہیں، آپ کے باقی والیٹ ڈیٹا کے ساتھ۔ یہ اپ لوڈ نہیں ہوتے،
اور والیٹ صاف کرنے پر باقی سب کے ساتھ مٹ جاتے ہیں۔

صرف دیکھنے والے اکاؤنٹس

صرف دیکھنے والا اکاؤنٹ ایسے پتے کو ٹریک کرتا ہے جس کی کلید آپ کے پاس نہیں ہے — کولڈ اسٹوریج،
ہارڈویئر والیٹ، ایکسچینج کا ڈپازٹ پتہ، یا کسی اور کا وہ پتہ جس پر آپ نظر رکھتے ہیں۔

Settings → 👥 Accounts → 👁 Watch Address کے تحت ایک شامل کریں: پتہ پیسٹ کریں، اسے
ایک نام دیں، اور یہ آپ کی اکاؤنٹ فہرست میں شامل ہو جاتا ہے۔

یہ کیا کر سکتا ہے: بیلنس دکھانا، ہسٹری درج کرنا، CSV ایکسپورٹ کرنا، اور بغیر PIN کے اس پر سوئچ کرنا —
ڈیکرپٹ کرنے کے لیے کوئی کیسٹور نہیں، لہٰذا ان لاک کرنے کے لیے کچھ نہیں۔

یہ کیا نہیں کر سکتا: کسی چیز پر دستخط نہیں کر سکتا۔ Send، خفیہ/ظاہر کرنا، اسٹیلتھ ٹرانسفر، کنٹریکٹ
کالز، اور dApp دستخط کی درخواستیں سب انکار کرتی ہیں، اور Send فارم آپ کو بھرنے سے پہلے ہی یہ بتا دیتا ہے
نہ کہ بعد میں۔ صرف دیکھنے والے اکاؤنٹس اکاؤنٹ فہرست اور ہیڈر میں 👁 سے نشان زد ہوتے ہیں،
تاکہ آپ کو ہمیشہ معلوم رہے کہ آپ کس قسم کو دیکھ رہے ہیں۔

صرف دیکھنے والے اکاؤنٹ کو اصلی اکاؤنٹ بنانے کے لیے، اس پتے کے لیے ریکوری فقرہ یا نجی کلید درآمد کریں۔
کلیدوں کا اضافہ ہی واحد طریقہ ہے؛ کوئی شارٹ کٹ نہیں۔

خفیہ کردہ بیلنس (FHE)

Orion Wallet آپ کے بیلنس کا کچھ حصہ مکمل ہومومورفک انکرپشن استعمال کرتے ہوئے خفیہ رکھ سکتا ہے،
تاکہ رقم چین پر عوامی طور پر نظر نہ آئے۔

یہ اختیاری ہے۔ باقی سب کچھ اس کے فعال یا غیر فعال ہونے سے قطع نظر کام کرتا ہے۔

اسے فعال کرنا

Settings → PVAC پر جائیں۔ دو اشارے دونوں سبز ہونے چاہئیں:

  • WASM Module — خفیہ نگاری کا ماڈیول لوڈ ہو چکا ہے
  • Bridge Initialized — اسے آپ کے والیٹ سیڈ سے کلید دی جا چکی ہے

اگر ان میں سے کوئی تیار نہ ہو تو پینل عین وجہ اور اس کا حل بیان کرتا ہے۔

خفیہ کرنا اور ظاہر کرنا

اپنے عوامی اور خفیہ بیلنس کے درمیان فنڈ منتقل کرنے کے لیے Encrypt استعمال کریں۔ یہ
کارروائیاں کمپیوٹیشنل طور پر بھاری ہیں اور کئی سیکنڈ لے سکتی ہیں؛ ایک پیش رفت ڈائیلاگ ہر مرحلہ دکھاتا ہے۔

اسٹیلتھ ٹرانسفرز

اسٹیلتھ ٹرانسفر رقم وصول کنندہ کی عوامی کلید سے اخذ کردہ یک وقتی پتے پر بھیجتے ہیں،
تاکہ ادائیگی ان کے مرکزی پتے سے عوامی طور پر منسلک نہ ہو سکے۔

Stealth کھولیں، وصول کنندہ اور رقم درج کریں، اور تصدیق کریں۔ وصول کنندہ اپنے
Stealth ٹیب سے فنڈز کا دعویٰ کرتا ہے۔

کسی dApp سے منسلک ہونا

جب کوئی ویب سائٹ کنکشن کی درخواست کرتی ہے تو ایک پاپ اپ ظاہر ہوتا ہے جو درخواست کرنے والے اوریجن کو دکھاتا ہے۔

منظور کرنے سے پہلے:

  • اوریجن کو غور سے چیک کریں۔ تصدیق کریں کہ ڈومین بالکل وہی سائٹ ہے جس کا آپ نے ارادہ کیا تھا۔
  • صرف ان اجازتوں کی منظوری دیں جن کی آپ توقع کرتے ہیں۔
  • "Trust this site" صرف پڑھنے والی درخواستوں کے لیے مستقبل کے پرامپٹس چھوڑ دیتا ہے — اسے کفایت سے استعمال کریں۔
  • پاپ اپ میں network سلیکٹر چیک کریں۔ یہ آپ کے ہر نیٹ ورک کو درج کرتا ہے، بشمول وہ جو آپ نے خود شامل کیے ہیں، تاکہ آپ پاپ اپ چھوڑے بغیر صحیح نیٹ ورک پر منسلک ہو سکیں۔

کسی بھی وقت Settings → Connected Sites کے تحت کنکشنز کا جائزہ لیں اور منسوخ کریں۔

لاک اور ان لاک کرنا

آپ کا PIN والیٹ کو ڈیکرپٹ کرتا ہے۔ ڈیکرپٹ شدہ کلیدیں پھر اس وقت تک دستیاب رہتی ہیں جب تک
ان لاک سیشن جاری ہے — ختم ہونے تک آپ سے دوبارہ PIN نہیں مانگا جاتا۔

  • صفحہ ریفریش کرنے سے آپ ان لاک رہتے ہیں۔ کلیدوں کو آپ کے موجودہ براؤزر ٹیب کے لیے دوبارہ سیل کیا جاتا ہے، لہٰذا ری لوڈ سیشن کو واپس اٹھا لیتا ہے بجائے اس کے کہ آپ کو PIN اسکرین پر لوٹا دے۔ اس دوران آپ کو مختصراً "Restoring your session…" نظر آئے گا۔
  • ٹیب بند کرنے سے سیشن ختم ہو جاتا ہے۔ سیل شدہ نقل صرف اسی ایک ٹیب تک محدود ہے اور اس کے ساتھ چلی جاتی ہے، لہٰذا نیا ٹیب یا ونڈو لاک حالت میں شروع ہوتا ہے۔
  • ہیڈر میں 🔒 فوراً لاک کر دیتا ہے اور سیل شدہ نقل کو تباہ کر دیتا ہے — لاک کرنے کے بعد ری لوڈ PIN مانگتا ہے، جیسا کہ ہونا چاہیے۔
  • بے عملی والیٹ کو لاک کر دیتی ہے پہلے سے طے شدہ طور پر 30 منٹ بعد، اور ایک ان لاک کبھی بھی 8 گھنٹے سے زیادہ نہیں رکھا جاتا چاہے سرگرمی کچھ بھی ہو۔

سیل شدہ سیشن کا کوئی بھی حصہ اکیلے کارآمد نہیں: خفیہ کردہ کلیدیں ٹیب کے پاس ہوتی ہیں،
جبکہ انہیں کھولنے والی کلید براؤزر ایسی شکل میں رکھتا ہے جسے کوئی صفحہ —

پاس کی سے ان لاک کرنا

اگر آپ کے آلے میں فنگر پرنٹ ریڈر، Face ID، Windows Hello، یا سیکیورٹی کی ہے تو آپ
PIN ٹائپ کرنے کے بجائے اس سے ان لاک کر سکتے ہیں۔

اسے Settings → 🔑 Security → Passkey Unlock → Enable passkey unlock کے تحت آن کریں۔ آپ کا
آلہ آپ سے رجسٹر کرنے کو کہتا ہے — یہ دو بار کہہ سکتا ہے، ایک بار پاس کی بنانے کے لیے اور ایک بار استعمال کرنے کے لیے۔ ان لاک اسکرین پھر PIN خانے کے اوپر 👆 Unlock with passkey پیش کرتی ہے۔

جاننا مفید ہے:

  • PIN اب بھی موجود ہے اور اب بھی اہم ہے۔ پاس کی والیٹ کھولتا ہے؛ یہ PIN کی جگہ نہیں لیتا۔ کلیدیں ایکسپورٹ کرنا، ریکوری فقرہ ظاہر کرنا، PIN تبدیل کرنا، اور نئے اکاؤنٹس اخذ کرنا سب اب بھی اسے مانگتے ہیں۔ PIN رکھیں — اسے کھونا پاس کی رکھنے سے حل نہیں ہوتا۔
  • یہ اس آلے اور اس براؤزر سے منسلک ہے۔ پاس کیز آپ کے والیٹ ڈیٹا کے ساتھ سفر نہیں کرتیں۔ دوسرے آلے پر، PIN سے ان لاک کریں اور وہاں پاس کی رجسٹر کریں اگر آپ چاہیں۔
  • آپ کا فنگر پرنٹ کبھی والیٹ تک نہیں پہنچتا۔ آلہ آپ کی تصدیق مقامی طور پر کرتا ہے اور صفحے کو پاس کی سے اخذ کردہ ایک راز دیتا ہے؛ وہی راز والیٹ کھولتا ہے۔
  • دستیابی آپ کے آلے اور براؤزر پر منحصر ہے۔ اگر آپ کا آلہ یہ نہیں کر سکتا، تو Security پینل یہ کہتا ہے اور آپشن بند رہتا ہے — PIN بالکل پہلے کی طرح کام کرتا رہتا ہے۔
  • اسی پینل میں پاس کی ان لاک بند کریں۔ یہ محفوظ شدہ نقل کو فوراً حذف کر دیتا ہے؛ یہ پاس کی کو آپ کے آلے سے نہیں ہٹاتا، جسے آپ اپنے OS یا براؤزر کی ترتیبات میں ہٹا سکتے ہیں۔

اگر پاس کی کبھی والیٹ کھولنا بند کر دے — گھمائی یا دوبارہ رجسٹر کی گئی اسناد، یا بحال شدہ آلہ — والیٹ یہ بتاتا ہے، پرانی نقل کو ضائع کرتا ہے، اور PIN مانگتا ہے۔ کچھ نہیں کھوتا؛ آپ بعد میں نئی پاس کی رجسٹر کر سکتے ہیں۔

صرف دیکھنے والا اکاؤنٹ فعال ہونے پر پاس کی ان لاک رجسٹر نہیں ہو سکتا — اس کے پاس کوئی کلید نہیں ہوتی،
لہٰذا پاس کی کو سیل کرنے کے لیے کچھ نہیں ہوتا۔ Security پینل بٹن کی جگہ یہی کہتا ہے۔

سیشن کی میعاد ختم ہونا

وہی حدود dApp کنکشنز پر لاگو ہوتی ہیں، جو خود بخود ختم ہو جاتے ہیں:

  • Idle timeout: 30 منٹ کی بے عملی
  • Absolute timeout: کنکشن سے 8 گھنٹے

جب سیشن ختم ہوتا ہے تو والیٹ کنکشن بند کر دیتا ہے اور dApp کو اطلاع دی جاتی ہے۔
پھر dApp کو آپ سے دوبارہ منسلک ہونے کو کہنا چاہیے۔

جب آپ کا سیشن ختم ہوتا ہے تو کیا ہوتا ہے

  1. والیٹ dApp کو ایک sessionExpired واقعہ بھیجتا ہے۔
  2. dApp میعاد ختم شدہ سیشن کا پتہ لگاتا ہے اور "Reconnect" پرامپٹ دکھاتا ہے۔
  3. آپ والیٹ پاپ اپ دوبارہ کھولنے کے لیے Connect پر کلک کرتے ہیں۔
  4. والیٹ آپ کا سیشن بحال کرتا ہے اور dApp دوبارہ شروع ہو جاتا ہے۔

اگر dApp خود بخود دوبارہ منسلک نہ ہو

  • dApp میں Connect بٹن پر کلک کریں۔
  • والیٹ پاپ اپ کھلتا ہے — کنکشن کی منظوری دیں۔
  • آپ کا پچھلا سیشن ڈیٹا محفوظ رہتا ہے، لہٰذا آپ کو اپنا والیٹ دوبارہ درآمد کرنے کی ضرورت نہیں۔

نیٹ ورک ترتیبات

Settings → ⚙️ General میں وہ RPC URL ہے جس سے والیٹ گفتگو کرتا ہے، وہ ایکسپلورر جس سے یہ لنک کرتا ہے،
اور ایک اختیاری پراکسی۔ RPC URL تبدیل کریں اور والیٹ کو کسی دوسرے نوڈ پر مبذول کرنے کے لیے Save URLs منتخب کریں۔

اپنا نیٹ ورک شامل کرنا

Devnet اور Mainnet والیٹ کے ساتھ آتے ہیں۔ کوئی اور شامل کرنے کے لیے — آپ کا اپنا نوڈ، ڈیو نیٹ فورک،
ادا شدہ RPC — اسی پینل میں Custom Networks تک اسکرول کریں اور یہ بھریں:

فیلڈدرکارنوٹس
نیٹ ورک کا نامہاںہر جگہ دکھایا جاتا ہے جہاں نیٹ ورک ظاہر ہوتا ہے، بشمول dApps کو
RPC URLہاںhttp:// یا https://
ایکسپلورر URLنہیںپہلے سے طے شدہ RPC URL

Add network منتخب کریں اور یہ فہرست میں شامل ہو جاتا ہے۔ اس کے بعد یہ ایک معمولی انتخاب ہے:

  • ٹاپ بار میں network pill کسی بھی پیش سیٹ کی طرح اس پر سوئچ کرتا ہے،
  • connect popup اسے درج کرتا ہے جب کوئی سائٹ منسلک ہونے کو کہتی ہے، بطور (custom)،
  • اور منسلک dApp اس کا نام اور ایکسپلورر پڑھ سکتا ہے تاکہ چیزیں درست لیبل کر سکے۔

نیٹ ورک سوئچ کرنے سے تینوں اینڈ پوائنٹس ایک ساتھ اپ ڈیٹ ہوتے ہیں — RPC، ایکسپلورر، اور relayer — تاکہ
والیٹ کبھی ایک نیٹ ورک پڑھتے ہوئے دوسرے سے لنک نہ کرے۔

نیٹ ورک کو اس کے ساتھ والے ✕ سے ہٹائیں۔ اگر آپ وہ حذف کرتے ہیں جس پر آپ اس وقت ہیں، تو والیٹ کسی پیش سیٹ پر گر جاتا ہے۔

dApp کیا دیکھتا ہے۔ جن سائٹس سے آپ منسلک ہوتے ہیں وہ کسٹم نیٹ ورک کا نام، آئیکن، ایکسپلورر
URL، اور یہ حقیقت پڑھ سکتی ہیں کہ آپ نے اسے شامل کیا۔ وہ اس کا RPC یا relayer URL نہیں پڑھ سکتیں —
ہوم نوڈ کا پتہ یا پرووائیڈر کی کلید والیٹ میں رہتی ہے۔ چونکہ نام نظر آتا ہے، اس لیے کسی ذاتی چیز کے نام پر نیٹ ورک نہ رکھیں۔

HTTPS کے بغیر نوڈس

ایک https:// نوڈ کو کسی خاص ہینڈلنگ کی ضرورت نہیں۔ صرف سادہ http:// پر دستیاب نوڈ
مختلف معاملہ ہے، کیونکہ والیٹ اس سے جو کچھ بھی پوچھتا ہے — ہر بیلنس اور ہسٹری
لک اپ، ہر جمع کرائی گئی ٹرانزیکشن — صاف متن میں سفر کرتا ہے، جہاں نیٹ ورک پاتھ پر موجود کوئی بھی اسے پڑھ سکتا ہے اور جواب بدل سکتا ہے۔ لہٰذا والیٹ پہلے پوچھتا ہے۔

  • Loopback کو اجازت کی ضرورت نہیں۔ localhost، 127.0.0.1، [::1] اور اسی طرح کے پتے کبھی
    آپ کی مشین سے نکلتے نہیں، لہٰذا لوکل نوڈ بغیر کسی ترتیب کے کام کرتا ہے۔
  • کسی بھی دوسرے http:// پتے پر واضح طور پر اعتماد کرنا ضروری ہے۔ URL پیسٹ کریں اور پینل
    اس کے ساتھ والے Trust http://… بٹن سے بتاتا ہے کہ داؤ پر کیا ہے۔ اعتماد ہر اوریجن
    (سکیم، ہوسٹ، اور پورٹ) کے حساب سے محفوظ ہوتا ہے، لہٰذا ایک نوڈ پر اعتماد دوسرے پر نہیں ہوتا، اور
    اسی ہوسٹ پر مختلف پورٹ ایک الگ فیصلہ ہے۔
  • Trusted plaintext endpoints درج کرتا ہے کہ آپ نے کس پر اعتماد کیا ہے، ساتھ Remove سے اسے
    واپس لینے کے لیے۔

دو حدود ایسی ہیں جنہیں ہم نہیں اٹھا سکتے، اور پینل بتاتا ہے کہ ان میں سے کون سی راہ میں حائل ہے:

  • https:// پر پیش کیا جانے والا والیٹ http:// بالکل نہیں لا سکتا۔ براؤزر اسے روکتے ہیں
    (اسے mixed content کہتے ہیں)، اور اوریجن پر اعتماد اسے نہیں بدلے گا۔ نوڈ کو TLS کے پیچھے رکھیں، پراکسی استعمال کریں، یا والیٹ کو سادہ-http یا localhost بلڈ سے کھولیں۔
  • شپ شدہ بلڈ صرف https:// اور loopback کی اجازت دیتا ہے۔ اس کی سیکیورٹی پالیسی بلڈ
    وقت پر طے ہوتی ہے اور چلتے ہوئے وسیع نہیں ہو سکتی۔ سیلف ہوسٹرز جنہیں سادہ http درکار ہے وہ
    VITE_ALLOW_HTTP_ENDPOINTS=1 سے بنا سکتے ہیں؛ اوپر والی اعتماد کی فہرست پھر بھی لاگو ہوتی ہے۔

ایکسپلورر URL ان سب سے مستثنیٰ ہے — یہ صرف ایک لنک ہے جس پر آپ کلک کرتے ہیں، والیٹ کے ذریعے لائی جانے والی کوئی چیز نہیں۔

RPC پراکسی

RPC proxy (اختیاری) کالز کو آپ کی پسند کے URL سے گزارتا ہے: RPC URL اس میں
جوڑا جاتا ہے، percent-encoded، اور براؤزر صرف پراکسی سے منسلک ہوتا ہے۔ یہ ان نوڈس کے لیے عملی حل ہے
جن کے پاس TLS یا CORS ہیڈر نہیں، اور یہ اوپر کے اصولوں کو پورا کرتا ہے کیونکہ براؤزر جو کنکشن بناتا ہے وہ پراکسی سے ہوتا ہے۔

پراکسی ہر وہ درخواست دیکھتا ہے جو والیٹ کرتا ہے، لہٰذا اپنی خود کی چلائیں۔ یہ کسی چیز پر دستخط نہیں کر سکتا
یا آپ کی کلیدوں تک نہیں پہنچ سکتا، لیکن یہ دیکھ سکتا ہے اور جھوٹ بول سکتا ہے۔

جب کچھ خراب ہو

اگر RPC اینڈ پوائنٹ ترتیب کے مطابق استعمال نہ ہو سکے، تو ہیڈر میں ⚠️ Insecure RPC ظاہر ہوتا ہے؛

عام طور پر RPC نوڈ ناقابلِ رسائی ہے یا CORS کو روک رہا ہے۔ Settings کے تحت RPC URL کی تصدیق کریں، اور CORS نوٹس دیکھیں۔ اگر غلطی کوئی وجہ بتاتی ہے —
سادہ متن، mixed content، یا بلڈ کی پابندی — نیٹ ورک ترتیبات دیکھیں؛ ایک RPC proxy CORS کی صورت حال ٹھیک کرتا ہے۔

ہیڈر "⚠️ Insecure RPC" دکھاتا ہے

ترتیب شدہ RPC اینڈ پوائنٹ سادہ http:// ہے اور جیسا ہے ویسے قابلِ استعمال نہیں۔ ترتیب کھولنے کے لیے
بیج منتخب کریں، جہاں عین وجہ اور حل درج ہیں۔ نیٹ ورک ترتیبات دیکھیں۔

📷 Scan منتخب کرنے پر کیمرہ نہیں کھلتا

  • کیمرے کی اجازت دیں جب براؤزر پوچھے؛ اگر آپ نے اسے مسترد کیا تو سائٹ کی اجازتوں میں دوبارہ اجازت دیں اور دوبارہ کوشش کریں۔
  • کیمرے تک رسائی کے لیے محفوظ صفحہ درکار ہے۔ یہ https:// اور localhost پر کام کرتا ہے، لیکن
    کسی دوسرے ہوسٹ پر سادہ-http:// صفحے پر نہیں۔
  • اگر کوئی اور ایپ کیمرہ پکڑے ہوئے ہے تو پہلے اسے بند کریں۔ آپ ہمیشہ اس کی بجائے پتہ پیسٹ کر سکتے ہیں۔

"Unlock with passkey" پیش نہیں کیا جاتا

یا تو اس براؤزر میں کوئی پاس کی رجسٹرڈ نہیں، یا آلہ وہ نہیں کر سکتا جو پاس کی ان لاک چاہتا ہے۔ Settings → 🔑 Security → Passkey Unlock بتاتا ہے کہ کون سا۔ پاس کیز ہر آلے اور ہر براؤزر کے حساب سے ہیں، لہٰذا کہیں اور رجسٹرڈ ایک یہاں ظاہر نہیں ہوتی۔ PIN ہمیشہ کام کرتا ہے۔
