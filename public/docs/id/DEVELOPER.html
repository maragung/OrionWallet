Penyiapan

npm install --legacy-peer-deps
npm run dev

--legacy-peer-deps bersifat wajib: ESLint 9 dan @eslint/js 10 mendeklarasikan rentang peer
yang saling bertentangan. vercel.json memakai flag yang sama, sehingga instalasi di CI dan lokal cocok.

Node 20+ direkomendasikan.

Arsitektur

Sepenuhnya sisi klien; tidak ada backend. Data mengalir dalam satu arah:

React components  (src/components/)
       │  read state, dispatch actions
       ▼
Zustand store  (src/store/wallet-store.ts)
       │
       ▼
API layer  (src/api/)          ← orchestrates crypto + RPC
       │
       ├──► Crypto core  (src/crypto/)   WebCrypto, tweetnacl, @noble
       ├──► PVAC FHE     (src/pvac/)     WebAssembly
       ├──► Transaction  (src/tx/)       canonical JSON + signing
       └──► RPC client   (src/rpc/)      fetch
                                           │ HTTPS
                                           ▼
                                    Octra RPC node

Batasan desain

Canonical JSON harus persis byte demi byte. src/tx/canonical-json.ts mereproduksi
urutan kunci dan pemformatan nlohmann::json secara persis. Tanda tangan dihitung atas byte-byte ini,
sehingga penyimpangan apa pun menghasilkan tanda tangan yang ditolak jaringan. Jangan "merapikan"
serializer ini.

Penamaan: produk versus protokol. "Orion Wallet" adalah produknya. Metode RPC octra_*,
prefiks alamat oct, ticker OCT, dan "Octra Network" adalah pengidentifikasi protokol
dan tidak boleh pernah diganti namanya.

Sistem build

File konfigurasi TypeScript adalah satu-satunya sumber kebenaran:

  • vite.config.ts
  • vitest.config.ts
  • playwright.config.ts
Jangan menambahkan padanan .js untuk file-file ini. Vite me-resolve vite.config.js mendahului
vite.config.ts, sehingga salinan hasil transpilasi yang basi diam-diam membayangi konfigurasi asli dan penyuntingan
pada file .ts tidak berpengaruh apa pun. Ketiga nama file itu ada di .gitignore.
eslint.config.js adalah flat config asli dan sengaja dipertahankan.

Mengabaikannya saja tidak cukup, karena tidak ada yang mencegahnya dibuat:
tsconfig.node.json adalah proyek composite, yang memaksa emit deklarasi, dan tanpa
outDir setiap tsc -b menulis vite.config.js langsung di samping sumber. Ini terjadi dua kali.
Emit untuk proyek itu kini diarahkan ke node_modules/.tmp/tsconfig-node/, tempat ia tidak bisa membayangi
apa pun. Bila Anda menambahkan file konfigurasi ke proyek itu, biarkan outDir apa adanya.

Flag lingkungan

FlagEfek
VITE_ALLOW_HTTP_ENDPOINTS=1Menambahkan http: ke direktif CSP connect-src saat build, sehingga build yang di-host sendiri bisa menjangkau node RPC http polos. Persetujuan pengguna per origin tetap berlaku — lihat src/wallet/endpoint-policy.ts

Hanya ditetapkan saat build. Ia dibaca di vite.config.ts oleh plugin allowHttpEndpointsCsp
dan menulis ulang index.html; ia tidak berpengaruh saat runtime, karena CSP berbasis meta-tag tidak bisa dilonggarkan
setelah dokumen selesai diurai.

Header

COOP/COEP disetel ke same-origin / require-corp (dicadangkan untuk threading WASM di masa depan),
dengan penggantian unsafe-none pada /connect agar transfer postMessage + MessagePort
milik popup berfungsi. Header dev berada di vite.config.ts; header produksi di vercel.json.
Jaga keduanya tetap sinkron.

Content-Security-Policy

Didefinisikan di index.html. script-src harus menyertakan 'wasm-unsafe-eval' — Chromium menolak
WebAssembly.instantiate() tanpanya, yang persis membuat modul PVAC gagal dimuat secara diam-diam. Direktif itu hanya mengizinkan kompilasi WebAssembly; ia tidak mengaktifkan kembali
eval() JavaScript.

connect-src adalah 'self' https: ditambah loopback (http://localhost:*, http://127.0.0.1:*,
http://[::1]:*) sehingga node yang dijalankan lokal berfungsi tanpa membuka plaintext secara umum. Selain itu,
apa pun melalui http:// dikendalikan oleh src/wallet/endpoint-policy.ts, satu-satunya tempat yang
memutuskan — fungsi murni dari URL ditambah konteks eksplisit, sehingga store, UI Settings,
dan pengujian tidak bisa saling bertentangan. Jangan menambahkan pemeriksaan URL dadakan di tempat lain. Tiga
penghalang independen berlaku (mixed content → CSP → persetujuan pengguna) dan putusannya melaporkan yang paling
fundamental lebih dulu, sehingga pengguna tidak pernah disuruh memperbaiki allowlist padahal browser-lah yang
menolak.

Pipeline WASM PVAC

Membangun

git clone https://github.com/emscripten-core/emsdk.git /tmp/emsdk
cd /tmp/emsdk && ./emsdk install latest && ./emsdk activate latest
source /tmp/emsdk/emsdk_env.sh

git clone https://github.com/octra-labs/webcli ../webcli-source
python3 scripts/patch-pvac-aes.py ../webcli-source/pvac   # software AES fallback
npm run build:wasm

patch-pvac-aes.py diperlukan karena PVAC memicu #error keras tanpa AES perangkat keras (AES-NI atau
ekstensi kripto ARM), yang tidak disediakan WebAssembly. Patch ini menambahkan implementasi perangkat lunak
yang portabel yang identik bit demi bit tetapi kira-kira 5–10× lebih lambat. Sifatnya aditif: jalur
perangkat keras tidak disentuh, dan backup .hpp.bak ditulis.

Pemuatan

src/pvac/wasm-bridge.ts memuat modul dalam tiga langkah:

  1. Probe — HEAD pada URL glue, sehingga "not built" (404) dapat dibedakan dari "blocked by CSP". Tanpa ini keduanya muncul sebagai kegagalan impor buram yang identik.
  2. Import — import() dinamis atas URL absolut dengan /* @vite-ignore */. Harus absolut: specifier telanjang gagal di-resolve, dan ./wasm/pvac.js di-resolve terhadap /assets/ lalu menghasilkan 404.
  3. Verify — pastikan seluruh 13 ekspor _pvac_* yang diperlukan ada sebelum menukar bridge. Build terdahulu melewatkan fungsi serialisasi, yang merusak enkripsi/dekripsi dengan cara yang hanya dilaporkan node sebagai "malformed transaction".

Kegagalan diklasifikasikan sebagai PvacFailureReason: not-built, csp-blocked,
missing-exports, init-failed, unknown. Masing-masing dipetakan ke solusi konkret yang ditampilkan di
Settings. Promise singleton di-reset saat gagal sehingga ↻ Reload PVAC bisa mencoba lagi alih-alih
memutar ulang penolakan yang di-cache.

Aturan memori

C API bersifat memori manual. Setiap _malloc membutuhkan _free; setiap serialize_* mengembalikan
buffer yang harus dilepaskan dengan _pvac_free_bytes. Handle dari keygen/enc_* membutuhkan
_pvac_free_* yang bersesuaian. Gunakan try/finally — lihat WasmPvacBridge untuk polanya.

Manajemen state

Zustand, di src/store/wallet-store.ts. Ia memiliki wallet, klien RPC, pengaturan, status PVAC,
toast, dan flag loading global.

Flag loading global (isLoading) menggerakkan overlay blur layar penuh dan dicadangkan untuk
transisi seluruh aplikasi saja, seperti membuka kunci wallet. Pekerjaan per panel harus memakai
usePanelLoading — lihat di bawah.

Penanganan error

src/components/ErrorBoundary.tsx membungkus setiap panel di Layout.tsx, dikunci berdasarkan tab
yang aktif sehingga boundary yang terpicu di-reset saat navigasi, ditambah satu boundary di root pada main.tsx.

Ini lebih penting daripada kelihatannya. index.html berisi:

#root:empty::before { content: 'Loading Orion Wallet…'; }

Tanpa boundary, throw apa pun saat render membuat React 18 melepas seluruh pohon, #root
menjadi kosong, dan fallback itu dirender — menghasilkan halaman putih kosong yang tampak macet
memuat selamanya. Boundary menjaga shell tetap hidup dan menampilkan kartu error yang bisa dicoba ulang.

Konsekuensi: fungsi yang dipanggil saat render tidak boleh throw pada input yang tidak sesuai bentuk.
formatAmount di src/tx/builder.ts menerima unknown dan menurunkan diri menjadi placeholder,
karena baik respons RPC maupun cache tx lokal tidak divalidasi skemanya. Normalisasikan
baris yang tidak tepercaya sebelum merendernya — HistoryView menunjukkan polanya.

Status pemuatan

Gunakan usePanelLoading (src/hooks/usePanelLoading.ts) untuk pekerjaan bercakupan panel:

const panelLoading = usePanelLoading();

await panelLoading.run('Loading history', async () => {
  const data = await fetchSomething();
  if (!panelLoading.isMounted()) return;   // guard late setState
  setData(data);
}, 'Fetching from the network…');

Lalu render <ProcessingModal open={panelLoading.loading} … dismissible onClose={panelLoading.hide} />.

Dua properti penting: modal bersifat dismissible (pekerjaan berlanjut di latar belakang, sehingga
jaringan yang lambat tidak pernah menjebak pengguna), dan penulisan state dijaga oleh isMounted() sehingga
berpindah halaman di tengah proses tidak bisa meninggalkan modal macet di layar.

Penyimpanan dan migrasi

IndexedDB melalui idb, database orion-wallet, versi 6. Store dideklarasikan satu kali di
array OBJECT_STORES di src/wallet/storage.ts; tambahkan yang baru di sana agar pembuatan dan
migrasi tetap konsisten — array itu juga menggerakkan wipeEverything(), sehingga store yang ditambahkan
di tempat lain akan lolos dari penghapusan menyeluruh.

Migrasi bersifat aditif saja: naikkan DB_VERSION, tambahkan ke array, dan catat
versinya dalam komentar di samping entri baru. Store yang ada tidak pernah diganti nama atau dibuang.
Versi sejauh ini: v2 store SDK, v3 token OCS01, v4 bookmark oct://, v5
unlock-session-keys, v6 contacts + passkey-unlock.

Migrasi rebrand

Mengganti nama database dari webcli-react akan membuat setiap wallet yang ada menjadi terlantar, karena
IndexedDB mencakup data berdasarkan nama database. migrateLegacyDatabase menyalin semua store maju pada
peluncuran pertama. Ia bersifat:

  • idempoten — dilewati begitu target memiliki wallet apa pun
  • non-destruktif — database lama dibiarkan utuh untuk rollback
  • non-fatal — kegagalan dicatat, tidak pernah di-throw; bug migrasi tidak boleh menghalangi startup

Ingat bahwa clearIndexedDB di helper E2E harus menghapus kedua database, atau
migrasi menyalin kembali data lama begitu saja dan "clean state" menjadi tidak bersih.

Wallet SDK

src/sdk/ adalah provider yang menghadap dApp; src/connect/ adalah popup persetujuan yang
dilayani di /connect.

Siklus hidup koneksi

Handshake (sekali per sesi):

  1. dApp memanggil provider.connect() → PopupTransport membuka /connect?v=1&rid=…&origin=…
  2. Wallet merender ConnectApp, pengguna membuka kunci bila diperlukan
  3. Wallet mengirim hello + MessagePort melalui window.postMessage, origin-nya divalidasi
  4. dApp menggemakan challenge melalui port (anti-replay)
  5. ConnectHandler memverifikasi ack, melayani RPC CONNECT → mengembalikan alamat, akun, jaringan

Setelah connect:

  • Popup boleh menutup, tetapi MessagePort tetap terbuka — ia independen dari jendela
  • Sesi disimpan di IndexedDB (sdk-sessions) dengan TTL idle + absolut
  • Metode baca (getBalance, getAccounts) bersifat session-silent
  • Metode penandatanganan selalu membuka prompt persetujuan baru

Perbaikan untuk "connect berhasil, selebihnya tidak":

Semula PopupTransport.isConnected() memeriksa popup.closed, sehingga setiap panggilan setelah
jendela persetujuan ditutup gagal dengan "Transport is not connected". Kini ia hanya memeriksa
port, yang berumur lebih panjang daripada popup. Wallet menutup popup setelah persetujuan, tetapi
koneksinya tetap hidup.

Model izin

Saat connect: Hanya scope baca-saja (viewAccounts, viewBalance, viewNetwork).

Scope penandatanganan (signMessage, signContract, dll.) diberikan secara lazy pada
persetujuan sukses pertama. Sebelum perbaikan, scope-scope itu tidak ada di DEFAULT_PERMISSIONS dan
dispatcher menolak setiap panggilan penandatanganan dengan UNAUTHORIZED sebelum prompt sempat muncul —
akar penyebab kedua dari gejala tersebut.

Sekarang:

  • Pemeriksaan izin membiarkan scope penandatanganan yang belum diberikan lanjut ke prompt persetujuan
  • Saat disetujui, grantPermission menyimpan scope itu ke sesi
  • Panggilan berikutnya melewati pemeriksaan izin tetapi tetap memerlukan persetujuan — memberikan sebuah scope hanya mencatat bahwa pengguna setuju dApp boleh meminta

Pencabutan bersifat eksplisit: revokePermission menghapus scope dari permissions dan mencatatnya
di deniedPermissions, yang ditolak dispatcher secara langsung.

Invarian keamanan

Jangan melemahkan hal-hal berikut:

  • Validasi origin pada setiap postMessage masuk (PopupTransport.ts, rpc-handler.ts)
  • Anti-replay: challenge CSPRNG + nonce dApp + nonce monoton per sesi. makeId hanya untuk korelasi pesan dan tidak boleh pernah dipakai sebagai nilai keamanan
  • Izin bersifat per origin, disimpan di sdk-sessions, dan diberikan/dicabut secara eksplisit
  • Independensi MessagePort: Port berumur lebih panjang daripada popup. Setelah ditransfer, wallet bisa menutup jendela persetujuan tanpa memutus koneksi
  • Metode yang dilarang ditolak baik di sisi klien (WalletProvider) maupun di sisi wallet (rpc-handler), sehingga eksekusi transaksi tidak akan pernah bisa lolos ke SDK bahkan melalui escape hatch tingkat rendah request()
  • localStorage hanya menyimpan petunjuk pemulihan sesi (alamat, jaringan) — tidak pernah rahasia

Integrasi dApp

Mulai cepat

import { WalletProvider } from '@orion-wallet/sdk';

const provider = new WalletProvider({
  walletUrl: 'https://orionwallet.example/connect',
  capabilities: [
    'signMessage',
    'signTypedData',
    'approveContract',
    'signContract',
    'multiAccount',
    'events',
    'sessionRestore',
    'customNetworks',
  ],
});

const result = await provider.connect();

Manajemen sesi

Sesi Orion kedaluwarsa setelah idle 30 menit atau 8 jam absolut. SDK menyediakan
pemeriksaan kesehatan sesi bawaan dan penyambungan ulang otomatis:

// Check session health before every signing operation
if (!provider.isSessionAlive()) {
  await provider.refreshSession();
}

// Listen for session expiry events
provider.on('sessionExpired', () => {
  setConnected(false);
});

Jaringan, termasuk milik pengguna sendiri

Pengguna bisa menambahkan jaringannya sendiri di Settings → Network (node mereka sendiri, fork devnet, atau
RPC berbayar). Jaringan tersebut bersifat first-class: mereka muncul di pemilih pada popup connect
bersama preset, dan dApp yang terhubung bisa melihatnya.

// Which network am I on? A record, not just an id string.
const active = await provider.getNetworkInfo();
// { id: 'home-node', name: 'Home node', explorerUrl: 'https://octrascan.io',
//   icon: '🏠', custom: true }

// Everything the wallet offers — presets first, user-added ones after.
const all = await provider.getNetworks();
const userAdded = all.filter((n) => n.custom);

// Cached from the connect reply, no round-trip; null before connect.
provider.networkInfo();

provider.on('networkChanged', ({ network, chainId, networkInfo }) => {
  // networkInfo is present on wallets that granted `customNetworks`.
  setChain(networkInfo?.name ?? network);
});

Lakukan feature-detect pada kapabilitas customNetworks sebelum mengandalkan apa pun dari ini — build
wallet yang lebih lama hanya menjawab wallet_getNetwork polos, yang mengembalikan string id.

NetworkInfo sengaja tidak membawa rpcUrl maupun relayerUrl. Jaringan yang
ditambahkan pengguna sering kali merupakan endpoint privat — alamat LAN, sebuah tunnel, URL penyedia dengan
API key di query string — dan menyerahkannya ke setiap situs yang dihubungi pengguna akan
membocorkan infrastruktur mereka. dApp tidak membutuhkannya: setiap pembacaan berjalan melalui wallet
(wallet_getBalance dan kawan-kawan) dan eksekusi tidak pernah keluar dari UI wallet. Yang melintasi
jaringan adalah apa yang memang sah dibutuhkan dApp — jaringan mana yang sedang diajak bicara, apakah
pemiliknya menambahkannya secara manual (custom), dan ke mana menautkan sebuah transaksi (explorerUrl).

Tidak ada wallet_switchNetwork. Pergantian tetap berada di UI wallet sendiri — pemilih di
popup atau pill jaringan di jendela utama — konsisten dengan aturan bahwa perubahan state tidak pernah
berasal dari dApp. dApp yang membutuhkan jaringan lain meminta pengguna untuk berganti, lalu menunggu
networkChanged.

networkChanged dipancarkan dari kedua tempat pergantian bisa terjadi: popup connect dan
jendela utama. Sesi diserahkan ke jendela utama saat popup ditutup, sehingga pada saat kebanyakan
pengguna menyentuh pill jaringan, popup sudah lama hilang — Layout.tsx memancarkan ke handler yang
telah diadopsi sehingga dApp yang terhubung tidak dibiarkan menampilkan jaringan yang basi.

Dua kelas independen mengimplementasikan WalletHost — src/connect/host.ts (jendela utama) dan
host inline di src/connect/ConnectApp.tsx (popup). Apa pun yang ditambahkan ke antarmuka harus
diimplementasikan di keduanya, ditambah fixture di tests/unit/connect-handler.test.ts.

Metode yang dilarang

SDK memblokir metode-metode ini secara lokal sebelum mencapai transport. Wallet juga memeriksa ulang di sisi
server, sehingga eksekusi transaksi tidak akan pernah bisa lolos:

  • wallet_sendTransaction / sendTransaction
  • wallet_broadcastTransaction / broadcastTransaction
  • wallet_transfer / transfer
  • wallet_swap / swap
  • wallet_bridge / bridge

Manajemen sesi

Sesi Orion Wallet dikelola secara otomatis oleh SDK. Sesi kedaluwarsa setelah:

  • Batas idle: 30 menit tanpa aktivitas
  • Batas absolut: 8 jam sejak koneksi

dApp bisa memeriksa kesehatan sesi kapan saja:

if (!provider.isSessionAlive()) {
  await provider.refreshSession();
}

Saat sesi kedaluwarsa, wallet memancarkan event sessionExpired. dApp seharusnya
mendengarkan event ini dan meminta pengguna menyambung ulang:

provider.on('sessionExpired', () => {
  // Prompt user to reconnect
  setConnected(false);
});

Pemulihan sesi ditangani secara otomatis — wallet menyimpan petunjuk sesi di
IndexedDB, sehingga menyambung ulang setelah kedaluwarsa tidak mengharuskan pengguna mengimpor ulang wallet-nya.

Catatan E2E: sebelum memercayai deretan kegagalan Playwright, periksa mesinnya, bukan diff-nya.
Dua batasan lingkungan menghasilkan kegagalan yang persis seperti regresi sungguhan:

  • Ruang temp. Chromium menempatkan setiap profil browser di bawah TMPDIR (/tmp secara bawaan). Bila filesystem itu penuh — mudah terjadi ketika /tmp adalah tmpfs kecil yang dibagi dengan proses lain — konteks mati saat diluncurkan dan pengujian yang tidak terkait gagal dalam hitungan milidetik, atau menggantung sampai timeout 30 dtk. df -h /tmp lebih dulu; jalankan ulang dengan TMPDIR=$HOME/.cache/e2e-tmp di filesystem yang lapang dan spec yang sama berubah dari timeout menjadi lulus dalam ~4 dtk.
  • Memori. Kira-kira 2 GB memori bebas per worker. Saat habis, Chromium dimatikan di tengah pengujian dan Playwright melaporkan Target crashed; jalankan ulang dengan --workers=1.

playwright.config.ts menyetel reuseExistingServer: !isCI, sehingga sisa npm run preview pada
port 4173 diam-diam dipakai ulang — termasuk yang dijalankan dari checkout berbeda. Saat
membandingkan dua tree, matikan listener di antara run (ss -lptn | grep 4173) atau run kedua
menguji build milik yang pertama.

Saat memperbaiki bug, tambahkan pengujian yang mendokumentasikan mode kegagalannya, bukan sekadar perbaikannya.
tests/unit/history-view.test.ts dan error-boundary.test.tsx mengikuti ini: masing-masing menyebutkan
gejala yang dicegahnya agar tidak terulang.

Daftar periksa rilis

  1. npm run autofix — harus sepenuhnya hijau
  2. npm run test:e2e terhadap npm run build yang segar
  3. npm audit --omit=dev — produksi harus melaporkan nol kerentanan
  4. Verifikasi PVAC dimuat di preview produksi (npm run preview), bukan hanya dev
  5. Uji jalur migrasi dari build pra-rebrand dengan data wallet yang sudah ada
  6. Pastikan header server vite.config.ts masih cocok dengan vercel.json

Masalah yang diketahui

Advisory dependency dev. npm audit melaporkan kerentanan pada vitest, vite, esbuild,
dan paket terkait. Setiap perbaikan yang tersisa membutuhkan upgrade mayor (vite 5→8, vitest 2→4).
Ini hanya build-tooling dan tidak dikirim ke pengguna; audit produksi bersih. Lihat
SECURITY.md.

Peringatan chunking storage.ts. Build memperingatkan bahwa storage.ts diimpor baik secara statis maupun
dinamis, sehingga ia tidak bisa dipecah menjadi chunk-nya sendiri. Tidak berbahaya, tetapi berarti
impor dinamis di HistoryView dan WalletExportImport tidak memberi manfaat code-splitting.

Performa AES perangkat lunak. Fallback AES WASM 5–10× lebih lambat daripada native. Operasi PVAC
yang berat memblokir main thread; memindahkannya ke Web Worker adalah langkah logis berikutnya.
