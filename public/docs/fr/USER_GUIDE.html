Orion Wallet — Guide de l'utilisateur

Orion Wallet fonctionne entièrement dans votre navigateur. Vos clés sont générées localement, chiffrées
avec votre code PIN, et stockées uniquement sur votre propre appareil. Rien n'est envoyé à un serveur.

GitHub: github.com/maragung/OrionWallet — Code source, signalements et versions.

Pour commencer

Prérequis

  • Une version récente de Chrome, Edge, Firefox ou Safari
  • JavaScript activé
  • Environ 4 Go de RAM si vous prévoyez d'utiliser les fonctions de solde chiffré

L'exécuter

Utilisez un déploiement hébergé, ou exécutez-le localement :

npm install --legacy-peer-deps
npm run dev

Ouvrez ensuite <http://localhost:5173>.

Créer un portefeuille

  1. Sélectionnez Create New Wallet, nommez le compte et choisissez un code PIN. Le code PIN chiffre le portefeuille sur cet appareil.
  2. Notez votre phrase de récupération. On vous affiche 12 mots. Recopiez-les sur papier dans l'ordre exact indiqué.
  3. Sélectionnez I've Written It Down. Le portefeuille vous demande alors de ressaisir 3 des mots, choisis au hasard, pour prouver que la phrase a réellement quitté l'écran. Show Phrase Again
    la réaffiche si vous avez besoin d'un autre coup d'œil ; une réponse erronée vous laisse simplement réessayer.
  4. Une fois les mots validés, le portefeuille s'ouvre.
Créer le portefeuille ne l'ouvre pas — c'est la réussite du test des mots qui l'ouvre. Jusque-là, vous
pouvez encore quitter l'écran sans rien perdre, car la phrase n'a pas encore été utilisée.
Votre phrase de récupération est le seul moyen de restaurer votre portefeuille. Quiconque la détient
contrôle vos fonds. Conservez-la hors ligne. Ne la photographiez jamais, ne la saisissez jamais sur un site web
et ne la collez jamais dans un chat ou un e-mail.

Importer un portefeuille existant

Choisissez Import puis sélectionnez l'une des options suivantes :

  • Recovery phrase — saisissez vos 12/24 mots
  • Private key — collez une clé privée base64
  • Wallet file — importez un fichier .oct chiffré et saisissez son code PIN

Utilisation courante

Consulter votre solde

L'onglet Balance affiche votre solde public et, si PVAC est activé, votre solde chiffré.

Recevoir

Ouvrez Receive pour afficher votre adresse et un code QR. Votre adresse est publique et peut être
partagée sans risque.

Vous pouvez aussi demander un montant précis. Le code QR porte alors le montant en plus de l'adresse (au
format octra:<address>?amount=<OCT>), si bien qu'un portefeuille qui le scanne préremplit les deux.
Sans montant demandé, le code reste une simple adresse, que n'importe quel lecteur peut lire.

Envoyer

  1. Ouvrez Send.
  2. Indiquez le destinataire de la manière qui vous convient :
  • Collez l'adresse (elle commence par oct).
  • Choisissez un nom enregistré dans 📇 Contacts….
  • Sélectionnez 📷 Scan pour lire un code QR avec votre caméra. Le navigateur demande l'autorisation
    d'accès à la caméra la première fois ; l'image est traitée dans la page et jamais téléversée. Le scan
    d'un code qui contient un montant remplit aussi ce montant.
  1. Saisissez un montant.
  2. Vérifiez les frais et le nonce, puis confirmez avec votre code PIN.

Lorsque l'adresse correspond à un contact enregistré, le formulaire affiche le nom à côté d'elle — un nom que vous
reconnaissez est un bien meilleur contrôle qu'une chaîne de caractères base58. Pour une nouvelle adresse, ＋ Save to
contacts l'enregistre sous un libellé de votre choix, pour que le prochain paiement soit une sélection, non un collage.

Vérifiez toujours le premier et le dernier caractère de l'adresse du destinataire avant de confirmer.
Les transactions sont irréversibles.

Historique

History répertorie les transactions récentes. Lorsque le réseau est injoignable, les entrées en cache
sont affichées et marquées ⚠ Cached.

⤓ exporte le tableau vers un fichier CSV (heure, hash, type, de, à, sens, montant, frais,
statut) pour un tableur ou vos propres archives. Il exporte les lignes actuellement chargées —
ce que vous voyez est ce que vous obtenez — utilisez donc Load more d'abord si vous voulez une plage plus étendue. Le
fichier est écrit par votre navigateur dans votre dossier de téléchargements ; rien n'est envoyé où que ce soit.

Contacts (carnet d'adresses)

Settings → 📇 Contacts conserve une liste d'adresses sous des noms que vous choisissez. Chaque entrée a
une adresse, un nom et une note facultative — un bon endroit pour noter « memo required » ou à quelle
plateforme d'échange appartient une adresse de dépôt.

Pourquoi s'en soucier : une adresse que vous ne pouvez pas lire est une adresse que vous ne pouvez pas vérifier. Dès qu'un
bénéficiaire est enregistré, le formulaire d'envoi le propose par son nom et étiquette l'adresse quand vous la recollez, si
bien qu'une adresse modifiée ou tronquée ressort au lieu de passer inaperçue.

  • Add une entrée ici, ou utilisez ＋ Save to contacts directement depuis le formulaire d'envoi.
  • ✎ renomme une entrée, 🗑 la supprime. Supprimer un contact n'a aucun effet on-chain.
  • ⤓ exporte la liste au format CSV, pour la conserver avec vos autres archives ou la déplacer vers un autre navigateur.

Les contacts vivent uniquement dans ce navigateur, avec le reste des données de votre portefeuille. Ils ne sont pas
téléversés, et ils sont effacés avec tout le reste si vous effacez le portefeuille.

Comptes watch-only

Un compte watch-only suit une adresse dont vous ne détenez pas les clés — un stockage à froid, un
portefeuille matériel, une adresse de dépôt d'une plateforme d'échange, ou l'adresse d'une autre personne que vous surveillez.

Ajoutez-en un sous Settings → 👥 Accounts → 👁 Watch Address : collez l'adresse, donnez-lui un
nom, et elle rejoint votre liste de comptes.

Ce qu'il peut faire : afficher le solde, lister l'historique, exporter en CSV, et être activé sans
code PIN — il n'y a pas de keystore à déchiffrer, donc rien à déverrouiller.

Ce qu'il ne peut pas faire : signer quoi que ce soit. L'envoi, le chiffrement/déchiffrement, les transferts furtifs, les appels de
contrat et les demandes de signature d'une dApp sont tous refusés, et le formulaire d'envoi le précise avant que vous le remplissiez,
plutôt qu'après. Les comptes watch-only sont marqués 👁 dans la liste des comptes et dans l'en-tête,
afin que vous sachiez toujours de quel type il s'agit.

Pour transformer un compte watch-only en véritable compte, importez la phrase de récupération ou la clé privée de
cette adresse. Ajouter les clés est le seul moyen ; il n'y a pas de raccourci.

Solde chiffré (FHE)

Orion Wallet peut conserver une partie de votre solde chiffrée à l'aide d'un chiffrement totalement homomorphe,
de sorte que le montant n'est pas visible publiquement sur la chaîne.

C'est facultatif. Tout le reste fonctionne, que ce soit activé ou non.

L'activer

Allez dans Settings → PVAC. Deux indicateurs doivent être tous deux verts :

  • WASM Module — le module cryptographique est chargé
  • Bridge Initialized — il a été initialisé avec une clé dérivée de la graine (seed) de votre portefeuille

Si l'un des deux n'est pas prêt, le panneau explique la cause exacte et la solution.

Chiffrer et déchiffrer

Utilisez Encrypt pour déplacer des fonds entre vos soldes public et chiffré. Ces
opérations sont coûteuses en calcul et peuvent prendre plusieurs secondes ; une fenêtre de progression
affiche chaque étape.

Transferts furtifs (stealth)

Les transferts furtifs envoient des fonds vers une adresse à usage unique dérivée de la clé publique du
destinataire, de sorte que le paiement n'est pas publiquement associable à son adresse principale.

Ouvrez Stealth, saisissez le destinataire et le montant, puis confirmez. Le destinataire récupère les
fonds depuis son propre onglet Stealth.

Se connecter à une dApp

Lorsqu'un site web demande une connexion, une fenêtre contextuelle apparaît et affiche l'origine de la requête.

Avant d'approuver :

  • Vérifiez soigneusement l'origine. Confirmez que le domaine est exactement le site que vous visiez.
  • N'approuvez que les autorisations que vous attendez.
  • « Trust this site » ignore les futures demandes de lecture seule — utilisez-le avec parcimonie.
  • Vérifiez le sélecteur de réseau dans la fenêtre contextuelle. Il liste tous les réseaux que vous avez,
    y compris ceux que vous avez ajoutés vous-même, pour que vous puissiez vous connecter au bon réseau sans quitter la fenêtre.

Vous pouvez consulter et révoquer les connexions à tout moment sous Settings → Connected Sites.

Verrouillage et déverrouillage

Votre code PIN déchiffre le portefeuille. Les clés déchiffrées restent ensuite disponibles pendant toute la durée
de la session de déverrouillage — on ne vous redemande pas le code PIN avant sa fin.

  • Actualiser la page vous laisse déverrouillé. Les clés sont de nouveau scellées pour l'onglet du navigateur
    dans lequel vous vous trouvez, si bien qu'un rechargement reprend la session au lieu de vous ramener à l'écran du code PIN.
    Vous verrez brièvement « Restoring your session… » pendant ce temps.
  • Fermer l'onglet met fin à la session. La copie scellée est limitée à cet onglet unique et
    disparaît avec lui, si bien qu'un nouvel onglet ou une nouvelle fenêtre démarre verrouillé.
  • 🔒 dans l'en-tête verrouille immédiatement et détruit la copie scellée — un rechargement après
    le verrouillage demande le code PIN, comme il se doit.
  • L'inactivité verrouille le portefeuille après 30 minutes par défaut, et un déverrouillage n'est
    jamais conservé plus de 8 heures, quelle que soit l'activité.

Aucune des deux moitiés de la session scellée n'est utile seule : les clés chiffrées sont détenues par l'onglet,
tandis que la clé qui les ouvre est conservée par le navigateur sous une forme qu'aucune page —
y compris celle-ci — ne peut relire.

Sous Settings → Security → Session & Auto-Lock :

RéglageDéfautEffet
Rester déverrouillé après une actualisation de la pageActivéDésactivez-le pour exiger le code PIN à chaque rechargement
Verrouillage automatique après inactivité30 minutes5 / 15 / 30 / 60 minutes, ou jamais (jusqu'à la fermeture de l'onglet)

Les deux s'appliquent à la fois, y compris à la session déjà ouverte. Sur un ordinateur partagé ou non fiable,
désactivez le premier et verrouillez le portefeuille lorsque vous vous éloignez.

Déverrouiller avec une passkey

Si votre appareil dispose d'un lecteur d'empreintes, de Face ID, de Windows Hello ou d'une clé de sécurité, vous pouvez
déverrouiller avec celui-ci au lieu de saisir le code PIN.

Activez-le sous Settings → 🔑 Security → Passkey Unlock → Enable passkey unlock. Votre
appareil vous invite à vous enregistrer — il peut vous inviter deux fois, une fois pour créer la passkey et
une fois pour l'utiliser. L'écran de déverrouillage propose alors 👆 Unlock with passkey au-dessus du champ du code PIN.

À savoir :

  • Le code PIN existe toujours et compte toujours. La passkey ouvre le portefeuille ; elle ne
    remplace pas le code PIN. L'exportation des clés, l'affichage de la phrase de récupération, le changement de code PIN et la
    dérivation de nouveaux comptes exigent toujours celui-ci. Conservez votre code PIN — le perdre n'est pas réparé par le fait d'avoir une passkey.
  • Elle est liée à cet appareil et à ce navigateur. Les passkeys ne voyagent pas avec les données de votre
    portefeuille. Sur un autre appareil, déverrouillez avec le code PIN et enregistrez-y une passkey si vous en voulez une.
  • Votre empreinte n'atteint jamais le portefeuille. L'appareil vous vérifie localement et remet
    à la page un secret dérivé de la passkey ; c'est ce secret qui ouvre le portefeuille.
  • La disponibilité dépend de votre appareil et de votre navigateur. Si le vôtre ne peut pas faire ce que cela exige,
    le panneau de sécurité le dit et l'option reste désactivée — le code PIN continue de fonctionner exactement comme avant.
  • Désactivez le déverrouillage par passkey dans le même panneau. Cela supprime immédiatement la copie stockée ;
    cela ne supprime pas la passkey de votre appareil, que vous pouvez retirer dans les réglages de votre système
    d'exploitation ou de votre navigateur.

Si une passkey cesse un jour d'ouvrir le portefeuille — un identifiant modifié ou ré-enregistré, ou un appareil
restauré — le portefeuille le dit, écarte la copie obsolète et demande le code PIN. Rien n'est perdu ;
vous pouvez enregistrer une nouvelle passkey ensuite.

Le déverrouillage par passkey ne peut pas être enregistré pendant qu'un compte watch-only est actif — il ne détient
aucune clé, donc il n'y a rien à sceller pour une passkey. Le panneau de sécurité le dit à la place du bouton.

Expiration de session

Les mêmes fenêtres régissent les connexions aux dApps, qui expirent automatiquement :

  • Délai d'inactivité : 30 minutes sans activité
  • Délai absolu : 8 heures à partir de la connexion

Lorsqu'une session expire, le portefeuille ferme la connexion et la dApp en est informée.
La dApp devrait alors vous inviter à vous reconnecter.

Ce qui se passe à l'expiration de votre session

  1. Le portefeuille émet un événement sessionExpired vers la dApp.
  2. La dApp détecte la session expirée et affiche une invite « Reconnect ».
  3. Vous cliquez sur Connect pour rouvrir la fenêtre du portefeuille.
  4. Le portefeuille restaure votre session et la dApp reprend.

Si une dApp ne se reconnecte pas automatiquement

  • Cliquez sur le bouton Connect dans la dApp.
  • La fenêtre du portefeuille s'ouvre — approuvez la connexion.
  • Les données de votre session précédente sont conservées, vous n'avez donc pas besoin de réimporter votre portefeuille.

Paramètres réseau

Settings → ⚙️ General contient l'URL RPC à laquelle le portefeuille parle, l'explorateur vers lequel il crée des liens,
et un proxy facultatif. Modifiez l'URL RPC puis sélectionnez Save URLs pour pointer le portefeuille
vers un autre nœud.

Ajouter votre propre réseau

Devnet et Mainnet sont fournis avec le portefeuille. Pour en ajouter un autre — votre propre nœud, un fork de devnet,
un RPC payant — faites défiler jusqu'à Custom Networks dans le même panneau et remplissez :

ChampRequisRemarques
Nom du réseauouiAffiché partout où le réseau apparaît, y compris aux dApps
URL RPCouihttp:// ou https://
URL de l'explorateurnonPar défaut, l'URL RPC
URL du relayernonNécessaire uniquement pour les transferts furtifs

Sélectionnez Add network et il rejoint la liste. Dès lors, c'est un choix ordinaire :

  • la pastille de réseau dans la barre supérieure permet de basculer vers lui comme n'importe quel préréglage,
  • la fenêtre de connexion le liste lorsqu'un site demande à se connecter, marqué (custom),
  • et une dApp connectée peut lire son nom et son explorateur pour libeller correctement les choses.

Changer de réseau met à jour les trois points d'accès ensemble — RPC, explorateur et relayer — afin que le
portefeuille ne se retrouve jamais à lire un réseau tout en créant des liens vers un autre.

Retirez un réseau avec le ✕ qui se trouve à côté. Si vous supprimez celui sur lequel vous êtes actuellement, le
portefeuille revient à un préréglage.

Ce qu'une dApp voit. Les sites auxquels vous vous connectez peuvent lire le nom, l'icône, l'URL de l'explorateur
d'un réseau personnalisé, ainsi que le fait que vous l'avez ajouté. Ils ne peuvent pas lire son URL RPC ou de relayer —
l'adresse d'un nœud personnel ou une clé de fournisseur reste dans le portefeuille. Comme le nom est visible, évitez de
nommer un réseau d'après quelque chose de personnel.

Nœuds sans HTTPS

Un nœud https:// ne demande aucun traitement particulier. Un nœud accessible uniquement en http:// simple
est une autre affaire, car tout ce que le portefeuille lui demande — chaque consultation de solde et d'historique, chaque
transaction soumise — circule en clair, là où n'importe qui sur le chemin réseau peut le lire et modifier les réponses.
Le portefeuille demande donc d'abord votre accord.

  • La boucle locale ne demande aucune autorisation. localhost, 127.0.0.1, [::1] et autres
    ne quittent jamais votre machine, donc un nœud local fonctionne immédiatement.
  • Toute autre adresse http:// doit être explicitement approuvée. Collez l'URL et le panneau
    explique ce qui est en jeu avec un bouton Trust http://… à côté. La confiance est stockée
    par origine (schéma, hôte et port), donc approuver un nœud n'en approuve pas un autre, et un port différent
    sur le même hôte est une décision distincte.
  • Points d'accès en clair approuvés liste ce que vous avez approuvé, avec Remove pour retirer votre confiance.

Deux limites ne dépendent pas de nous, et le panneau nomme celle qui fait obstacle :

  • Un portefeuille servi en https:// ne peut pas du tout aller chercher du http://. Les navigateurs bloquent cela
    (c'est ce qu'on appelle le contenu mixte), et approuver l'origine n'y changera rien. Mettez le nœud
    derrière TLS, utilisez un proxy, ou ouvrez le portefeuille depuis une version en http simple ou en localhost.
  • La version distribuée n'autorise que https:// et la boucle locale. Sa politique de sécurité est figée
    au moment de la compilation et ne peut pas être élargie à l'exécution. Les auto-hébergeurs qui ont besoin de http simple peuvent
    compiler avec VITE_ALLOW_HTTP_ENDPOINTS=1 ; la liste de confiance ci-dessus s'applique en plus.

L'URL de l'explorateur est exempte de tout cela — c'est seulement un lien sur lequel vous cliquez, pas
quelque chose que le portefeuille va chercher.

Proxy RPC

RPC proxy (optional) achemine les appels à travers une URL de votre choix : l'URL RPC y est ajoutée,
encodée en pourcentage, et le navigateur ne se connecte qu'au proxy. C'est la solution pratique pour un nœud sans TLS
ou sans en-têtes CORS, et cela satisfait les règles ci-dessus parce que la connexion que le navigateur établit va au proxy.

Le proxy voit chaque requête du portefeuille, donc faites tourner le vôtre. Il ne peut rien signer
ni atteindre vos clés, mais il peut observer et il peut mentir.

Quand quelque chose ne va pas

Si le point d'accès RPC ne peut pas être utilisé tel qu'il est configuré, ⚠️ Insecure RPC apparaît dans l'en-tête ;
sélectionnez-le pour accéder directement au réglage. Les erreurs réseau portent aussi la raison, donc un simple
« Failed to fetch » vous indique quoi corriger.

Sauvegarde et récupération

Exporter

Settings → Backup → Export télécharge un fichier .oct chiffré. Il est protégé par
votre code PIN, mais traitez-le comme sensible.

Restaurer

Utilisez Import → Wallet file et fournissez le code PIN en vigueur au moment de l'exportation du fichier.

Plusieurs comptes

Settings → Accounts dérive des comptes supplémentaires de la même phrase de récupération. Une seule
phrase les restaure tous.

Deux choses que la phrase ne restaure pas, car elles n'en ont jamais été dérivées :

  • Les comptes watch-only — ce sont simplement des adresses que vous avez demandé au portefeuille de suivre.
    Notez-les séparément si vous voulez les retrouver après une réinstallation.
  • Les contacts — exportez-les avec ⤓ sous Settings → Contacts s'ils comptent pour vous.

Ni l'un ni l'autre ne détient de fonds, donc les perdre vous coûte du confort, pas de l'argent.

Dépannage

La page est vide ou reste bloquée au chargement

Rechargez. Si cela persiste, une carte d'erreur avec un bouton Retry devrait apparaître. Signalez le
message qui y est affiché.

Le solde chiffré est indisponible

« Failed to load history » / erreurs réseau

C'est généralement le nœud RPC qui est injoignable ou qui bloque CORS. Vérifiez l'URL RPC sous
Settings, et consultez les notes sur CORS. Si l'erreur nomme une raison —
texte en clair, contenu mixte ou restriction de compilation — voir
Paramètres réseau ; un RPC proxy corrige le cas CORS.

L'en-tête affiche « ⚠️ Insecure RPC »

Le point d'accès RPC configuré est en http:// simple et n'est pas utilisable en l'état. Sélectionnez le
badge pour ouvrir le réglage, où la cause exacte et le correctif sont détaillés. Voir
Paramètres réseau.

La caméra ne s'ouvre pas quand je sélectionne 📷 Scan

  • Accordez l'autorisation d'accès à la caméra quand le navigateur la demande ; si vous l'avez ignorée,
    réautorisez-la dans les permissions du site et réessayez.
  • L'accès à la caméra nécessite une page sécurisée. Cela fonctionne sur https:// et sur localhost, mais pas sur
    une page en http:// simple sur un autre hôte.
  • Si une autre application tient la caméra, fermez-la d'abord. Vous pouvez toujours coller l'adresse à la place.

« Unlock with passkey » n'est pas proposé

Soit aucune passkey n'est enregistrée dans ce navigateur, soit l'appareil ne peut pas faire ce que le déverrouillage
par passkey exige. Settings → 🔑 Security → Passkey Unlock le précise. Les passkeys sont propres
à chaque appareil et à chaque navigateur, donc celle enregistrée ailleurs n'apparaît pas ici. Le code PIN fonctionne toujours.

J'ai oublié mon code PIN

Réinstallez le portefeuille avec votre phrase de récupération et définissez un nouveau code PIN. Sans la phrase,
les fonds ne peuvent pas être récupérés — par personne.

« Could not read your saved wallets » / « Could not read your accounts »

Le portefeuille n'a pas pu ouvrir sa base de données locale. Rien n'a été supprimé — c'est presque
toujours un autre onglet Orion, ou une fenêtre Connect restée ouverte, qui maintient la base de données ouverte.
Après une mise à jour, le navigateur ne mettra pas à niveau la base de données tant qu'un ancien onglet y est
encore rattaché.

Fermez les autres onglets et fenêtres Orion, puis sélectionnez ↻ Try again. Si le message persiste,
fermez tous les onglets Orion et rouvrez le portefeuille dans un seul onglet.

L'écran de déverrouillage distingue les deux états à dessein : No stored wallet found signifie que la base
de données est réellement vide, tandis que Could not read your saved wallets signifie que vos comptes sont là mais
temporairement inaccessibles. Ne créez pas un nouveau portefeuille pendant que vous voyez le second message.

Mon portefeuille a disparu après une mise à jour

Les données sont migrées automatiquement depuis les anciennes versions au premier lancement. Si vos comptes ont
disparu, ne créez pas un nouveau portefeuille — cela pourrait écraser les anciennes données. Signalez le
problème et restaurez depuis votre phrase de récupération en attendant.

La dApp dit « Session expired »

Cela signifie que la session du portefeuille a expiré (30 min d'inactivité / 8 h au maximum). Reconnectez-vous en
cliquant sur Connect dans la dApp. Les données de votre portefeuille sont conservées — vous devez seulement
réapprouver la connexion.

Protéger vos fonds

À faire

  • Conservez votre phrase de récupération hors ligne, sur papier, idéalement à plusieurs endroits
  • Vérifiez les adresses des destinataires avant d'envoyer
  • Vérifiez l'origine affichée dans les invites de connexion des dApps
  • Commencez par une petite transaction de test lors d'un premier envoi vers une nouvelle adresse
  • Enregistrez les bénéficiaires comme contacts et vérifiez le nom — un nom que vous reconnaissez vaut mieux que de lire du base58
  • Utilisez un compte watch-only pour surveiller un stockage à froid, au lieu de déverrouiller le vrai compte

À ne jamais faire

  • Saisir votre phrase de récupération sur un site web. Orion Wallet ne vous la demandera jamais après la configuration
  • Stocker la phrase dans une capture d'écran, une note d'un gestionnaire de mots de passe, un disque cloud ou un chat
  • Partager votre clé privée ou votre fichier .oct
  • Utiliser un portefeuille contenant de vrais fonds sur un ordinateur partagé ou non fiable

Orion Wallet n'a pas fait l'objet d'un audit indépendant. Veuillez consulter le
document de sécurité avant d'y conserver des valeurs importantes.
