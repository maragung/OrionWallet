Orion Wallet — Benutzerhandbuch

Orion Wallet läuft vollständig in Ihrem Browser. Ihre Schlüssel werden lokal erzeugt, mit
Ihrer PIN verschlüsselt und nur auf Ihrem eigenen Gerät gespeichert. Nichts wird an einen Server gesendet.

GitHub: github.com/maragung/OrionWallet — Quellcode, Issues und Releases.

Erste Schritte

Voraussetzungen

  • Eine aktuelle Version von Chrome, Edge, Firefox oder Safari
  • Aktiviertes JavaScript
  • Etwa 4 GB RAM, wenn Sie die Funktionen für verschlüsseltes Guthaben nutzen möchten

Ausführen

Nutzen Sie eine gehostete Bereitstellung oder führen Sie es lokal aus:

npm install --legacy-peer-deps
npm run dev

Öffnen Sie anschließend <http://localhost:5173>.

Ein Wallet erstellen

  1. Wählen Sie Create New Wallet, benennen Sie das Konto und wählen Sie eine PIN. Die PIN verschlüsselt das Wallet auf diesem Gerät.
  2. Notieren Sie Ihre Wiederherstellungsphrase. Es werden Ihnen 12 Wörter angezeigt. Schreiben Sie sie in der exakt angegebenen Reihenfolge auf Papier ab.
  3. Wählen Sie I've Written It Down. Das Wallet fordert Sie anschließend auf, 3 der Wörter erneut einzugeben, die zufällig ausgewählt werden, um zu bestätigen, dass die Phrase den Bildschirm tatsächlich verlassen hat. Show Phrase Again
    blendet sie wieder ein, falls Sie sie noch einmal ansehen möchten; eine falsche Antwort lässt Sie einfach erneut versuchen.
  4. Sobald die Wörter bestätigt sind, öffnet sich das Wallet.
Das Erstellen des Wallets öffnet es nicht — erst das Bestehen der Wortprüfung tut das. Bis dahin können Sie
noch jederzeit aussteigen, und nichts geht verloren, weil die Phrase noch nicht verwendet wurde.
Ihre Wiederherstellungsphrase ist die einzige Möglichkeit, Ihr Wallet wiederherzustellen. Wer sie besitzt,
kontrolliert Ihr Guthaben. Bewahren Sie sie offline auf. Fotografieren Sie sie niemals, geben Sie sie nie auf einer Website ein
und fügen Sie sie nie in einen Chat oder eine E-Mail ein.

Ein vorhandenes Wallet importieren

Wählen Sie Import und entscheiden Sie sich für eine der folgenden Optionen:

  • Wiederherstellungsphrase — geben Sie Ihre 12/24 Wörter ein
  • Privater Schlüssel — fügen Sie einen privaten base64-Schlüssel ein
  • Wallet-Datei — laden Sie eine verschlüsselte .oct-Datei hoch und geben Sie deren PIN ein

Täglicher Gebrauch

Ihr Guthaben prüfen

Die Registerkarte Balance zeigt Ihr öffentliches Guthaben und, wenn PVAC aktiviert ist, Ihr verschlüsseltes Guthaben.

Empfangen

Öffnen Sie Receive, um Ihre Adresse und einen QR-Code anzuzeigen. Ihre Adresse ist öffentlich und kann
gefahrlos geteilt werden.

Sie können auch einen bestimmten Betrag anfordern. Der QR-Code enthält dann den Betrag zusammen mit
der Adresse (als octra:<address>?amount=<OCT>), sodass ein Wallet, das ihn scannt, beide Felder vorausfüllt.
Wird kein Betrag angefordert, bleibt der Code eine reine Adresse, die jeder Scanner lesen kann.

Senden

  1. Öffnen Sie Send.
  2. Geben Sie den Empfänger auf die für Sie passende Weise an:
  • Fügen Sie die Adresse ein (sie beginnt mit oct).
  • Wählen Sie einen gespeicherten Namen aus 📇 Contacts….
  • Wählen Sie 📷 Scan, um mit Ihrer Kamera einen QR-Code zu lesen. Der Browser fragt beim ersten Mal nach der Kameraberechtigung; das Bild wird auf der Seite verarbeitet und niemals hochgeladen.
    Auch das Scannen eines Codes, der einen Betrag enthält, füllt den Betrag aus.
  1. Geben Sie einen Betrag ein.
  2. Prüfen Sie die Gebühr und die Nonce und bestätigen Sie anschließend mit Ihrer PIN.

Wenn die Adresse mit einem gespeicherten Kontakt übereinstimmt, zeigt das Formular den Namen daneben an — ein Name, den Sie
wiedererkennen, ist eine weitaus bessere Prüfung als eine Zeichenfolge aus base58. Für eine neue Adresse speichert sie ＋ Save to
contacts unter einer von Ihnen gewählten Bezeichnung, sodass die nächste Zahlung eine Auswahl und kein Einfügen ist.

Überprüfen Sie stets die ersten und letzten Zeichen der Empfängeradresse, bevor Sie bestätigen.
Transaktionen können nicht rückgängig gemacht werden.

Verlauf

History listet die letzten Transaktionen auf. Wenn das Netzwerk nicht erreichbar ist, werden zwischengespeicherte Einträge
angezeigt und mit ⚠ Cached gekennzeichnet.

⤓ exportiert die Tabelle in eine CSV-Datei (Zeit, Hash, Typ, Von, An, Richtung, Betrag, Gebühr,
Status) für eine Tabellenkalkulation oder Ihre eigenen Aufzeichnungen. Exportiert werden die aktuell geladenen Zeilen —
was Sie sehen, erhalten Sie — verwenden Sie daher zunächst Load more, wenn Sie einen größeren Bereich möchten. Die
Datei wird von Ihrem Browser in Ihren Download-Ordner geschrieben; nichts wird irgendwohin gesendet.

Kontakte (Adressbuch)

Settings → 📇 Contacts führt eine Liste von Adressen unter von Ihnen gewählten Namen. Jeder Eintrag hat
eine Adresse, einen Namen und eine optionale Notiz — ein guter Ort für „memo required" oder dafür, zu welcher
Börse eine Einzahlungsadresse gehört.

Warum der Aufwand: Eine Adresse, die Sie nicht lesen können, ist eine Adresse, die Sie nicht prüfen können. Sobald ein Zahlungsempfänger
gespeichert ist, bietet das Send-Formular ihn namentlich an und beschriftet die Adresse, wenn Sie sie wieder einfügen, sodass
eine vertauschte oder abgeschnittene Adresse auffällt, statt unbemerkt zu bleiben.

  • Fügen Sie hier mit Add einen Eintrag hinzu oder verwenden Sie ＋ Save to contacts direkt aus dem Send-Formular.
  • ✎ benennt einen Eintrag um, 🗑 entfernt ihn. Das Entfernen eines Kontakts hat keine Auswirkungen on-chain.
  • ⤓ exportiert die Liste als CSV, sodass sie mit Ihren anderen Aufzeichnungen aufbewahrt oder in einen anderen Browser übertragen werden kann.

Kontakte existieren nur in diesem Browser, zusammen mit den übrigen Daten Ihres Wallets. Sie werden nicht
hochgeladen und werden zusammen mit allem anderen gelöscht, wenn Sie das Wallet löschen.

Beobachtungskonten (Watch-only)

Ein Beobachtungskonto verfolgt eine Adresse, für die Sie nicht die Schlüssel besitzen — Cold Storage, eine
Hardware-Wallet, eine Einzahlungsadresse einer Börse oder die Adresse einer anderen Person, die Sie im Blick behalten.

Fügen Sie eines unter Settings → 👥 Accounts → 👁 Watch Address hinzu: Fügen Sie die Adresse ein, geben Sie ihr einen
Namen, und sie wird Teil Ihrer Kontoliste.

Was es kann: das Guthaben anzeigen, den Verlauf auflisten, CSV exportieren und ohne
PIN aktiviert werden — es gibt keinen Keystore zu entschlüsseln, also gibt es nichts zu entsperren.

Was es nicht kann: irgendetwas signieren. Senden, Ver-/Entschlüsseln, Stealth-Überweisungen, Vertrags-
aufrufe und dApp-Signaturanfragen werden allesamt abgelehnt, und das Send-Formular weist darauf hin, bevor Sie es ausfüllen,
statt danach. Beobachtungskonten sind in der Kontoliste und in der
Kopfzeile mit 👁 markiert, sodass Sie stets wissen, welche Art Sie vor sich haben.

Um ein Beobachtungskonto in ein echtes umzuwandeln, importieren Sie die Wiederherstellungsphrase oder den privaten Schlüssel für
diese Adresse. Das Hinzufügen der Schlüssel ist der einzige Weg; es gibt keine Abkürzung.

Verschlüsseltes Guthaben (FHE)

Orion Wallet kann einen Teil Ihres Guthabens mithilfe vollständig homomorpher Verschlüsselung verschlüsselt halten,
sodass der Betrag on-chain nicht öffentlich sichtbar ist.

Dies ist optional. Alles andere funktioniert unabhängig davon, ob es aktiviert ist.

Aktivieren

Gehen Sie zu Settings → PVAC. Zwei Anzeigen müssen beide grün sein:

  • WASM Module — das kryptografische Modul wurde geladen
  • Bridge Initialized — es wurde mit einem Schlüssel aus Ihrem Wallet-Seed initialisiert

Falls eine davon nicht bereit ist, erläutert das Panel die genaue Ursache und die Behebung.

Verschlüsseln und Entschlüsseln

Verwenden Sie Encrypt, um Guthaben zwischen Ihrem öffentlichen und Ihrem verschlüsselten Guthaben zu verschieben. Diese
Vorgänge sind rechenintensiv und können mehrere Sekunden dauern; ein Fortschrittsdialog
zeigt jede Phase an.

Stealth-Überweisungen

Stealth-Überweisungen senden Guthaben an eine Einmaladresse, die aus dem öffentlichen
Schlüssel des Empfängers abgeleitet wird, sodass die Zahlung öffentlich nicht mit dessen Hauptadresse verknüpfbar ist.

Öffnen Sie Stealth, geben Sie Empfänger und Betrag ein und bestätigen Sie. Der Empfänger fordert das
Guthaben über seine eigene Stealth-Registerkarte an.

Verbindung mit einer dApp

Wenn eine Website eine Verbindung anfordert, erscheint ein Popup, das den anfragenden Origin anzeigt.

Vor dem Genehmigen:

  • Prüfen Sie den Origin sorgfältig. Vergewissern Sie sich, dass die Domain exakt die von Ihnen beabsichtigte Website ist.
  • Genehmigen Sie nur die Berechtigungen, die Sie erwarten.
  • „Trust this site" überspringt künftige Abfragen für schreibgeschützte Anfragen — verwenden Sie es sparsam.
  • Prüfen Sie den Netzwerk-Selektor im Popup. Er listet jedes Netzwerk auf, das Sie haben, einschließlich der von Ihnen selbst hinzugefügten, sodass Sie sich im richtigen Netzwerk verbinden können, ohne das Popup zu verlassen.

Überprüfen und widerrufen Sie Verbindungen jederzeit unter Settings → Connected Sites.

Sperren und Entsperren

Ihre PIN entschlüsselt das Wallet. Die entschlüsselten Schlüssel bleiben dann so lange verfügbar, wie die
Entsperrsitzung andauert — Sie werden erst wieder nach der PIN gefragt, wenn sie endet.

  • Ein Neuladen der Seite hält Sie entsperrt. Die Schlüssel werden für die Browser-Registerkarte, in der Sie sich befinden, erneut versiegelt, sodass ein Neuladen die Sitzung wieder aufnimmt, statt Sie zum PIN-
    Bildschirm zurückzubringen. Währenddessen sehen Sie kurz „Restoring your session…".
  • Das Schließen der Registerkarte beendet die Sitzung. Die versiegelte Kopie ist auf diese eine Registerkarte beschränkt und verschwindet mit ihr, sodass eine neue Registerkarte oder ein neues Fenster gesperrt startet.
  • 🔒 in der Kopfzeile sperrt sofort und zerstört die versiegelte Kopie — ein Neuladen nach dem Sperren fragt nach der PIN, so wie es sein sollte.
  • Inaktivität sperrt das Wallet standardmäßig nach 30 Minuten, und eine einzelne Entsperrung wird unabhängig von der Aktivität niemals länger als 8 Stunden fortgeführt.

Keine der beiden Hälften der versiegelten Sitzung ist für sich allein nützlich: Die verschlüsselten Schlüssel werden von der
Registerkarte gehalten, während der Schlüssel, der sie öffnet, vom Browser in einer Form aufbewahrt wird, die keine Seite —
auch diese nicht — wieder auslesen kann.

Unter Settings → Security → Session & Auto-Lock:

EinstellungStandardFunktion
Nach einem Neuladen der Seite entsperrt bleibenAnAusschalten, um bei jedem Neuladen die PIN zu verlangen
Automatisch sperren nach Inaktivität30 Minuten5 / 15 / 30 / 60 Minuten oder nie (bis die Registerkarte geschlossen wird)

Beide gelten sofort, auch für die bereits geöffnete Sitzung. Auf einem gemeinsam genutzten oder
nicht vertrauenswürdigen Computer schalten Sie die erste Option aus und sperren das Wallet, wenn Sie sich entfernen.

Mit einem Passkey entsperren

Wenn Ihr Gerät über einen Fingerabdruckleser, Face ID, Windows Hello oder einen Sicherheitsschlüssel verfügt, können Sie
damit entsperren, anstatt die PIN einzugeben.

Aktivieren Sie es unter Settings → 🔑 Security → Passkey Unlock → Enable passkey unlock. Ihr
Gerät fordert Sie zur Registrierung auf — es kann Sie zweimal auffordern, einmal zum Erstellen des Passkeys und
einmal zu dessen Verwendung. Der Entsperrbildschirm bietet dann 👆 Unlock with passkey über dem PIN-Feld an.

Wissenswert:

  • Die PIN existiert weiterhin und ist weiterhin wichtig. Der Passkey öffnet das Wallet; er ersetzt die PIN nicht. Das Exportieren von Schlüsseln, das Anzeigen der Wiederherstellungsphrase, das Ändern der PIN und
    das Ableiten neuer Konten verlangen sie nach wie vor. Behalten Sie die PIN — deren Verlust wird nicht dadurch behoben,
    dass Sie einen Passkey haben.
  • Er ist an dieses Gerät und diesen Browser gebunden. Passkeys wandern nicht mit Ihren Wallet-Daten mit. Entsperren Sie auf einem anderen Gerät mit der PIN und registrieren Sie dort einen Passkey, falls Sie einen möchten.
  • Ihr Fingerabdruck erreicht das Wallet niemals. Das Gerät verifiziert Sie lokal und übergibt der Seite ein aus dem Passkey abgeleitetes Geheimnis; dieses Geheimnis öffnet das Wallet.
  • Die Verfügbarkeit hängt von Ihrem Gerät und Browser ab. Wenn Ihres nicht leisten kann, was hierfür erforderlich ist, weist das Security-Panel darauf hin und die Option bleibt aus — die PIN funktioniert genau wie
    zuvor.
  • Deaktivieren Sie das Passkey-Entsperren im selben Panel. Das löscht die gespeicherte Kopie sofort; es löscht den Passkey nicht von Ihrem Gerät, den Sie in Ihren Betriebssystem- oder
    Browsereinstellungen entfernen können.

Falls ein Passkey das Wallet einmal nicht mehr öffnet — ein rotiertes oder neu registriertes Credential oder ein
wiederhergestelltes Gerät — weist das Wallet darauf hin, verwirft die veraltete Kopie und fragt nach der PIN. Nichts
geht verloren; Sie können anschließend einen neuen Passkey registrieren.

Das Passkey-Entsperren kann nicht registriert werden, während ein Beobachtungskonto aktiv ist — es enthält keine Schlüssel,
sodass es für einen Passkey nichts zu versiegeln gibt. Das Security-Panel weist anstelle der Schaltfläche darauf hin.

Sitzungsablauf

Dieselben Zeitfenster gelten für dApp-Verbindungen, die automatisch ablaufen:

  • Leerlauf-Timeout: 30 Minuten Inaktivität
  • Absolutes Timeout: 8 Stunden ab Verbindung

Wenn eine Sitzung abläuft, schließt das Wallet die Verbindung und die dApp wird benachrichtigt.
Die dApp sollte Sie dann auffordern, sich erneut zu verbinden.

Was geschieht, wenn Ihre Sitzung abläuft

  1. Das Wallet sendet ein sessionExpired-Ereignis an die dApp.
  2. Die dApp erkennt die abgelaufene Sitzung und zeigt eine „Reconnect"-Aufforderung an.
  3. Sie klicken auf Connect, um das Wallet-Popup erneut zu öffnen.
  4. Das Wallet stellt Ihre Sitzung wieder her und die dApp wird fortgesetzt.

Wenn eine dApp sich nicht automatisch erneut verbindet

  • Klicken Sie in der dApp auf die Schaltfläche Connect.
  • Das Wallet-Popup öffnet sich — genehmigen Sie die Verbindung.
  • Ihre vorherigen Sitzungsdaten bleiben erhalten, sodass Sie Ihr Wallet nicht erneut importieren müssen.

Netzwerkeinstellungen

Settings → ⚙️ General enthält die RPC-URL, mit der das Wallet kommuniziert, den Explorer, auf den es verlinkt,
und einen optionalen Proxy. Ändern Sie die RPC-URL und wählen Sie Save URLs, um das Wallet
auf einen anderen Node zu verweisen.

Ein eigenes Netzwerk hinzufügen

Devnet und Mainnet werden mit dem Wallet ausgeliefert. Um ein weiteres hinzuzufügen — Ihren eigenen Node, einen Devnet-Fork, ein
kostenpflichtiges RPC — scrollen Sie im selben Panel zu Custom Networks und füllen Sie aus:

FeldErforderlichHinweise
NetzwerknamejaWird überall angezeigt, wo das Netzwerk erscheint, auch gegenüber dApps
RPC-URLjahttp:// oder https://
Explorer-URLneinStandardmäßig die RPC-URL
Relayer-URLneinNur für Stealth-Überweisungen erforderlich

Wählen Sie Add network und es wird der Liste hinzugefügt. Von da an ist es eine normale Auswahl:

  • das Netzwerk-Pill in der oberen Leiste wechselt wie bei jeder Voreinstellung dorthin,
  • das Verbindungs-Popup listet es auf, wenn eine Website eine Verbindung anfordert, markiert mit (custom),
  • und eine verbundene dApp kann seinen Namen und Explorer lesen, sodass sie Dinge korrekt beschriftet.

Der Wechsel des Netzwerks aktualisiert alle drei Endpunkte zusammen — RPC, Explorer und Relayer —, sodass das
Wallet nie ein Netzwerk ausliest, während es auf ein anderes verlinkt.

Entfernen Sie ein Netzwerk mit dem ✕ daneben. Wenn Sie das gerade aktive löschen, greift das
Wallet auf eine Voreinstellung zurück.

Was eine dApp sieht. Websites, mit denen Sie sich verbinden, können den Namen, das Symbol, die Explorer-
URL eines benutzerdefinierten Netzwerks und die Tatsache lesen, dass Sie es hinzugefügt haben. Sie können dessen RPC- oder Relayer-URL nicht lesen — die Adresse eines Heim-
Nodes oder ein Anbieterschlüssel bleibt im Wallet. Da der Name sichtbar ist, vermeiden Sie es,
ein Netzwerk nach etwas Persönlichem zu benennen.

Nodes ohne HTTPS

Ein https://-Node erfordert keine besondere Behandlung. Ein Node, der nur über einfaches http:// erreichbar ist, ist
eine andere Sache, denn alles, was das Wallet ihn fragt — jede Guthaben- und Verlaufs-
abfrage, jede eingereichte Transaktion — wird im Klartext übertragen, wo jeder auf dem Netzwerk-
pfad es lesen und die Antworten verändern kann. Deshalb fragt das Wallet zuerst.

  • Loopback erfordert keine Berechtigung. localhost, 127.0.0.1, [::1] und Ähnliche verlassen niemals Ihren Rechner, sodass ein lokaler Node sofort funktioniert.
  • Jede andere http://-Adresse muss ausdrücklich als vertrauenswürdig eingestuft werden. Fügen Sie die URL ein, und das Panel erläutert mit einer Schaltfläche Trust http://… daneben, was auf dem Spiel steht. Vertrauen wird
    pro Origin gespeichert (Schema, Host und Port), sodass das Vertrauen in einen Node nicht das Vertrauen in einen anderen bedeutet und ein
    anderer Port auf demselben Host eine separate Entscheidung ist.
  • Trusted plaintext endpoints listet auf, was Sie als vertrauenswürdig eingestuft haben, mit Remove, um dies zurückzunehmen.

Zwei Einschränkungen können wir nicht aufheben, und das Panel benennt jeweils diejenige, die im Weg steht:

  • Ein über https:// ausgeliefertes Wallet kann http:// überhaupt nicht abrufen. Browser blockieren das (es wird Mixed Content genannt), und das Vertrauen in den Origin ändert daran nichts. Stellen Sie den Node
    hinter TLS, verwenden Sie einen Proxy oder öffnen Sie das Wallet aus einem Plain-HTTP- oder localhost-Build.
  • Der ausgelieferte Build erlaubt nur https:// und Loopback. Seine Sicherheitsrichtlinie ist zur Build-Zeit festgelegt und kann zur Laufzeit nicht erweitert werden. Selbst-Hoster, die einfaches HTTP benötigen, können
    mit VITE_ALLOW_HTTP_ENDPOINTS=1 bauen; die obige Vertrauensliste gilt weiterhin zusätzlich.

Die Explorer-URL ist von all dem ausgenommen — sie ist immer nur ein Link, den Sie anklicken, nicht
etwas, das das Wallet abruft.

RPC-Proxy

RPC proxy (optional) leitet Aufrufe über eine URL Ihrer Wahl weiter: Die RPC-URL wird
daran angehängt, prozentcodiert, und der Browser verbindet sich immer nur mit dem Proxy. Es ist die
praktische Lösung für einen Node ohne TLS oder ohne CORS-Header, und es erfüllt die obigen Regeln,
weil die Verbindung, die der Browser herstellt, zum Proxy führt.

Der Proxy sieht jede Anfrage, die das Wallet stellt, also betreiben Sie einen eigenen. Er kann nichts signieren
oder Ihre Schlüssel erreichen, aber er kann beobachten und er kann lügen.

Wenn etwas nicht stimmt

Wenn der RPC-Endpunkt nicht wie konfiguriert verwendet werden kann, erscheint ⚠️ Insecure RPC in der Kopfzeile;
wählen Sie es, um direkt zur Einstellung zu springen. Netzwerkfehler enthalten außerdem den Grund, sodass Ihnen ein bloßes
„Failed to fetch" sagt, was zu beheben ist.

Sicherung und Wiederherstellung

Exportieren

Settings → Backup → Export lädt eine verschlüsselte .oct-Datei herunter. Sie ist durch
Ihre PIN geschützt, behandeln Sie sie jedoch als sensibel.

Wiederherstellen

Verwenden Sie Import → Wallet file und geben Sie die PIN an, die beim Export der Datei verwendet wurde.

Mehrere Konten

Settings → Accounts leitet zusätzliche Konten aus derselben Wiederherstellungsphrase ab. Eine
Phrase stellt alle davon wieder her.

Zwei Dinge stellt die Phrase nicht wieder her, weil sie nie aus ihr abgeleitet wurden:

  • Beobachtungskonten — sie sind nur Adressen, die Sie das Wallet zu verfolgen gebeten haben. Notieren Sie sie separat, wenn Sie sie nach einer Neuinstallation zurückhaben möchten.
  • Kontakte — exportieren Sie sie mit ⤓ unter Settings → Contacts, wenn sie Ihnen wichtig sind.

Keines von beiden hält Guthaben, sodass ihr Verlust Sie Komfort kostet, nicht Geld.

Fehlerbehebung

Die Seite ist leer oder bleibt beim Laden hängen

Laden Sie neu. Falls es weiterhin auftritt, sollte eine Fehlerkarte mit einer Schaltfläche Retry erscheinen. Melden Sie die
dort angezeigte Meldung.

Verschlüsseltes Guthaben ist nicht verfügbar

Settings → PVAC zeigt eine der folgenden Meldungen an:

Drücken Sie ↻ Reload PVAC, nachdem Sie eine Behebung angewendet haben — kein Neustart erforderlich.

„Failed to load history" / Netzwerkfehler

Normalerweise ist der RPC-Node nicht erreichbar oder blockiert CORS. Überprüfen Sie die RPC-URL unter
Settings und lesen Sie die CORS-Hinweise. Wenn der Fehler einen Grund nennt —
Klartext, Mixed Content oder eine Build-Einschränkung — siehe
Netzwerkeinstellungen; ein RPC-Proxy behebt den CORS-Fall.

Die Kopfzeile zeigt „⚠️ Insecure RPC"

Der konfigurierte RPC-Endpunkt ist einfaches http:// und in diesem Zustand nicht verwendbar. Wählen Sie das
Abzeichen, um die Einstellung zu öffnen, in der die genaue Ursache und die Behebung dargelegt sind. Siehe
Netzwerkeinstellungen.

Die Kamera öffnet sich nicht, wenn ich 📷 Scan wähle

  • Erteilen Sie die Kameraberechtigung, wenn der Browser danach fragt; falls Sie sie abgelehnt haben, erlauben Sie sie erneut in den Website-Berechtigungen und versuchen Sie es noch einmal.
  • Der Kamerazugriff erfordert eine sichere Seite. Er funktioniert auf https:// und auf localhost, aber nicht auf einer einfachen http://-Seite auf einem anderen Host.
  • Wenn eine andere App die Kamera belegt, schließen Sie diese zuerst. Sie können die Adresse jederzeit stattdessen einfügen.

„Unlock with passkey" wird nicht angeboten

Entweder ist in diesem Browser kein Passkey registriert, oder das Gerät kann nicht leisten, was das Passkey-Entsperren
erfordert. Settings → 🔑 Security → Passkey Unlock gibt an, was zutrifft. Passkeys gelten pro Gerät
und pro Browser, sodass ein anderswo registrierter hier nicht erscheint. Die PIN funktioniert immer.

Ich habe meine PIN vergessen

Installieren Sie das Wallet mit Ihrer Wiederherstellungsphrase neu und legen Sie eine neue PIN fest. Ohne die Phrase
kann das Guthaben nicht wiederhergestellt werden — von niemandem.

„Could not read your saved wallets" / „Could not read your accounts"

Das Wallet konnte seine lokale Datenbank nicht öffnen. Nichts wurde gelöscht — dies ist fast
immer eine weitere Orion-Registerkarte oder ein übrig gebliebenes Connect-Popup, das die Datenbank noch offen hält.
Nach einem Update aktualisiert der Browser die Datenbank nicht, solange eine ältere Registerkarte noch
mit ihr verbunden ist.

Schließen Sie die anderen Orion-Registerkarten und Popups und wählen Sie dann ↻ Try again. Falls die Meldung bestehen bleibt,
schließen Sie jede Orion-Registerkarte und öffnen Sie das Wallet in einer einzigen Registerkarte erneut.

Der Entsperrbildschirm unterscheidet die beiden Zustände bewusst: No stored wallet found bedeutet, dass die
Datenbank wirklich leer ist, während Could not read your saved wallets bedeutet, dass Ihre Konten
vorhanden, aber vorübergehend nicht erreichbar sind. Erstellen Sie kein neues Wallet, während Sie die
zweite Meldung sehen.

Mein Wallet ist nach einem Update verschwunden

Daten werden beim ersten Start automatisch aus älteren Builds migriert. Falls Ihre Konten
fehlen, erstellen Sie kein neues Wallet — das könnte die alten Daten überschreiben. Melden Sie das
Problem und stellen Sie in der Zwischenzeit aus Ihrer Wiederherstellungsphrase wieder her.

dApp meldet „Session expired"

Das bedeutet, dass die Wallet-Sitzung abgelaufen ist (30 Min. Leerlauf / 8 Std. absolut). Verbinden Sie sich erneut, indem Sie
in der dApp auf Connect klicken. Ihre Wallet-Daten bleiben erhalten — Sie müssen nur
die Verbindung erneut genehmigen.

So schützen Sie Ihr Guthaben

Empfohlen

  • Bewahren Sie Ihre Wiederherstellungsphrase offline auf Papier auf, idealerweise an mehr als einem Ort
  • Überprüfen Sie Empfängeradressen vor dem Senden
  • Überprüfen Sie den in dApp-Verbindungsabfragen angezeigten Origin
  • Beginnen Sie mit einer kleinen Testtransaktion, wenn Sie an eine neue Adresse senden
  • Speichern Sie Zahlungsempfänger als Kontakte und prüfen Sie den Namen — ein Name, den Sie wiedererkennen, ist besser als base58 zu lesen
  • Verwenden Sie ein Beobachtungskonto, um Cold Storage im Blick zu behalten, statt das echte zu entsperren

Niemals

  • Ihre Wiederherstellungsphrase auf irgendeiner Website eingeben. Orion Wallet fragt nach der Einrichtung niemals danach
  • Die Phrase in einem Screenshot, einer Passwortmanager-Notiz, einem Cloud-Laufwerk oder einem Chat speichern
  • Ihren privaten Schlüssel oder Ihre .oct-Datei weitergeben
  • Ein Wallet mit echtem Guthaben auf einem gemeinsam genutzten oder nicht vertrauenswürdigen Computer verwenden

Orion Wallet wurde nicht unabhängig auditiert. Bitte lesen Sie das
Sicherheitsdokument, bevor Sie signifikante Werte speichern.
