Orion Wallet — 사용자 가이드

Orion Wallet은 전적으로 브라우저 안에서 실행됩니다. 귀하의 키는 로컬에서 생성되고 PIN으로 암호화되어
귀하의 기기에만 저장됩니다. 서버로 전송되는 것은 없습니다.

GitHub: github.com/maragung/OrionWallet — 소스 코드, 이슈, 릴리스.

시작하기

요구 사항

  • 최신 버전의 Chrome, Edge, Firefox 또는 Safari
  • JavaScript 활성화
  • 암호화 잔액 기능을 사용할 계획이라면 약 4GB의 RAM

실행하기

호스팅된 배포판을 사용하거나 로컬에서 실행할 수 있습니다.

npm install --legacy-peer-deps
npm run dev

그런 다음 <http://localhost:5173>을 엽니다.

지갑 만들기

  1. Create New Wallet을 선택하고 계정 이름을 지정한 다음 PIN을 선택합니다. PIN은 이 기기에서 지갑을 암호화합니다.
  2. 복구 문구를 종이에 적어 두십시오. 12개의 단어가 표시됩니다. 표시된 정확한 순서대로 종이에 옮겨 적으십시오.
  3. I've Written It Down을 선택합니다. 그러면 지갑은 구문이 실제로 화면을 떠났음을 증명하기 위해 무작위로 고른 3개의 단어를 다시 입력하도록 요청합니다. 다시 보고 싶다면 Show Phrase Again으로
    다시 표시할 수 있으며, 잘못 입력하면 다시 시도할 수 있을 뿐입니다.
  4. 단어 확인이 끝나면 지갑이 열립니다.
지갑을 만드는 것만으로는 열리지 않으며, 단어 확인을 통과해야 열립니다. 그때까지는
언제든 그만둘 수 있고 잃을 것도 없습니다. 아직 구문에 의존한 적이 없기 때문입니다.
복구 문구는 지갑을 복원할 수 있는 유일한 방법입니다. 이를 가진 사람은 누구나
귀하의 자금을 통제할 수 있습니다. 오프라인으로 보관하십시오. 절대 사진으로 찍거나 웹사이트에 입력하거나
채팅이나 이메일에 붙여넣지 마십시오.

PIN과 복구 문구의 차이

복구 문구PIN
용도어디서든 지갑을 복원합니다이 기기에서만 잠금을 해제합니다
분실 시자금을 복구할 수 없습니다복구 문구로 복원합니다
보관 위치귀하가 오프라인으로 보관저장되지 않음 — 귀하만 알고 있습니다

기존 지갑 가져오기

Import를 선택하고 다음 중 하나를 고릅니다.

  • Recovery phrase — 12/24개의 단어를 입력합니다
  • Private key — base64 개인 키를 붙여넣습니다
  • Wallet file — 암호화된 .oct 파일을 업로드하고 해당 PIN을 입력합니다

일상적인 사용

잔액 확인

Balance 탭에는 공개 잔액이 표시되며, PVAC가 활성화된 경우 암호화된 잔액도 표시됩니다.

받기

Receive를 열면 귀하의 주소와 QR 코드가 표시됩니다. 주소는 공개 정보이므로
공유해도 안전합니다.

특정 금액을 요청할 수도 있습니다. 그러면 QR 코드가 주소와 함께 금액을 담게 되며
(octra:<address>?amount=<OCT> 형식), 이를 스캔하는 지갑은 둘 다 자동으로 채웁니다.
금액을 요청하지 않으면 코드는 주소만 담은 상태로 남으며, 어떤 스캐너든 읽을 수 있습니다.

보내기

  1. Send를 엽니다.
  2. 수신자를 편리한 방식으로 지정합니다.
    • 주소를 붙여넣습니다(oct로 시작합니다).
    • 📇 Contacts…에서 저장된 이름을 선택합니다.
    • 📷 Scan을 선택하여 카메라로 QR 코드를 읽습니다. 처음에는 브라우저가 카메라 권한을 요청하며, 사진은 페이지 안에서 처리되고 결코 업로드되지 않습니다. 금액이 담긴 코드를 스캔하면 금액도 함께 채워집니다.
  3. 금액을 입력합니다.
  4. 수수료와 논스를 확인한 다음 PIN으로 확인합니다.

주소가 저장된 연락처와 일치하면 양식은 그 옆에 이름을 표시합니다. 귀하가 알아보는 이름이
base58 문자열보다 훨씬 좋은 확인 수단입니다. 새 주소라면 ＋ Save to contacts를 통해
원하는 라벨로 저장할 수 있으므로, 다음 결제는 붙여넣기가 아니라 선택이 됩니다.

확인 전에 항상 수신자 주소의 첫 자와 끝자를 검증하십시오.
거래는 되돌릴 수 없습니다.

기록(History)

History는 최근 거래를 나열합니다. 네트워크에 연결할 수 없으면 캐시된 항목이
표시되며 ⚠ Cached로 표시됩니다.

⤓는 표를 CSV 파일(시간, 해시, 유형, 발신자, 수신자, 방향, 금액, 수수료,
상태)로 내보내 스프레드시트나 귀하의 기록으로 보관할 수 있게 합니다. 내보내기는 현재 불러와진 행들을
내보냅니다. 즉, 보이는 것이 곧 얻는 것이므로 더 긴 범위를 원한다면 먼저 Load more를 사용하십시오. 이
파일은 브라우저가 귀하의 다운로드 폴더에 저장하며, 어디로도 전송되지 않습니다.

연락처(주소록)

Settings → 📇 Contacts는 귀하가 정한 이름 아래 주소 목록을 유지합니다. 각 항목에는
주소, 이름, 그리고 선택적인 메모가 있습니다. "memo required(메모 필요)"나 입금 주소가 어느
거래소에 속하는지 기록하기에 좋은 곳입니다.

왜 신경 써야 하는가: 읽을 수 없는 주소는 확인할 수 없는 주소입니다. 수취인이 저장되면
Send 양식은 이름으로 수취인을 제안하고, 주소를 다시 붙여넣을 때 라벨을 표시하므로
바뀌거나 잘린 주소가 눈에 띄지 않고 섞여 버리는 일이 없습니다.

  • 여기서 Add로 항목을 추가하거나, Send 양식에서 바로 ＋ Save to contacts를 사용합니다.
  • ✎는 항목 이름을 바꾸고 🗑는 항목을 제거합니다. 연락처를 제거해도 온체인상 아무 영향도 없습니다.
  • ⤓는 목록을 CSV로 내보내 다른 기록과 함께 보관하거나 다른 브라우저로 옮길 수 있게 합니다.

연락처는 나머지 지갑 데이터와 함께 이 브라우저에만 존재합니다. 업로드되지 않으며,
지갑을 초기화하면 다른 모든 것과 함께 삭제됩니다.

조회 전용 계정

조회 전용 계정은 귀하가 키를 보유하지 않은 주소를 추적합니다. 콜드 스토리지, 하드웨어 지갑,
거래소 입금 주소, 또는 귀하가 지켜보는 다른 사람의 주소 등입니다.

Settings → 👥 Accounts → 👁 Watch Address에서 추가할 수 있습니다. 주소를 붙여넣고
이름을 지정하면 계정 목록에 포함됩니다.

할 수 있는 일: 잔액 표시, 기록 나열, CSV 내보내기, 그리고 PIN 없이 전환 — 해독할 키 저장소가
없으므로 잠금을 해제할 대상도 없습니다.

할 수 없는 일: 서명은 불가능합니다. 보내기, 암호화/복호화, 스텔스 전송, 컨트랙트
호출, dApp 서명 요청이 모두 거부되며, Send 양식은 입력을 시작하기 전에 그 사실을 알려줍니다.
조회 전용 계정은 계정 목록과 헤더에서 👁로 표시되므로, 현재 어떤 종류를 보고 있는지 항상 알 수 있습니다.

조회 전용 계정을 실제 계정으로 바꾸려면 해당 주소의 복구 문구나 개인 키를 가져오십시오.
키를 추가하는 것만이 유일한 방법이며 지름길은 없습니다.

암호화 잔액(FHE)

Orion Wallet은 완전 동형 암호화(FHE)를 사용하여 잔액의 일부를 암호화한 상태로 보관할 수 있으므로,
그 금액이 온체인상에 공개적으로 드러나지 않습니다.

이 기능은 선택 사항입니다. 활성화 여부와 관계없이 다른 모든 기능은 동작합니다.

활성화하기

Settings → PVAC로 이동합니다. 두 지표가 모두 초록색이어야 합니다.

  • WASM Module — 암호화 모듈이 로드되었습니다
  • Bridge Initialized — 지갑 시드로부터 키가 생성되었습니다

둘 중 하나라도 준비되지 않았다면 패널이 정확한 원인과 해결책을 설명합니다.

암호화 및 복호화

Encrypt를 사용하여 공개 잔액과 암호화 잔액 사이에서 자금을 이동합니다. 이러한
작업은 계산량이 많아 몇 초가 걸릴 수 있으며, 진행 대화상자가 각 단계를 표시합니다.

스텔스 전송

스텔스 전송은 수신자의 공개 키에서 파생된 일회용 주소로 자금을 보내므로,
해당 지불이 수신자의 기본 주소와 공개적으로 연결되지 않습니다.

Stealth를 열고 수신자와 금액을 입력한 다음 확인합니다. 수신자는 자신의 Stealth 탭에서
자금을 수령합니다.

dApp 연결

웹사이트가 연결을 요청하면 요청하는 출처(origin)를 표시하는 팝업이 나타납니다.

승인하기 전에:

  • 출처를 주의 깊게 확인하십시오. 도메인이 의도한 사이트와 정확히 일치하는지 확인합니다.
  • 기대하는 권한만 승인하십시오.
  • "Trust this site"는 읽기 전용 요청에 대한 향후 프롬프트를 건너뜁니다 — 아껴서 사용하십시오.
  • 팝업의 network 선택기를 확인하십시오. 귀하가 직접 추가한 네트워크를 포함해 보유한
    모든 네트워크가 나열되므로, 팝업을 떠나지 않고 올바른 네트워크에 연결할 수 있습니다.

연결은 언제든 Settings → Connected Sites에서 검토하고 철회할 수 있습니다.

잠금 및 잠금 해제

PIN은 지갑을 복호화합니다. 복호화된 키는 잠금 해제 세션이 유지되는 동안 계속 사용할 수 있으며,
세션이 끝날 때까지 PIN을 다시 묻지 않습니다.

  • 페이지를 새로고침해도 잠금 해제 상태가 유지됩니다. 키가 현재 탭을 위해 다시 봉인되므로,
    새로고침하면 PIN 화면으로 돌아가는 대신 세션을 이어받습니다. 그동안 잠시 "Restoring your session…"이 표시됩니다.
  • 탭을 닫으면 세션이 종료됩니다. 봉인된 사본은 해당 탭에 한정되며
    탭과 함께 사라지므로, 새 탭이나 창은 잠긴 상태로 시작됩니다.
  • 헤더의 🔒는 즉시 잠그고 봉인된 사본을 파기합니다. 잠근 뒤의 새로고침은
    당연히 PIN을 요구합니다.
  • 비활성 상태는 기본적으로 30분 후 지갑을 잠그며, 한 번의 잠금 해제는
    활동 여부와 관계없이 8시간을 넘겨 유지되지 않습니다.

봉인된 세션의 두 절반은 각각 단독으로는 쓸모가 없습니다. 암호화된 키는 탭이 보관하고,
그 키를 여는 열쇠는 브라우저가 어떤 페이지도 — 이 페이지조차도 — 읽어낼 수 없는 형태로 보관합니다.

Settings → Security → Session & Auto-Lock 아래:

설정기본값기능
Stay unlocked after a page refresh켜짐끄면 모든 새로고침에서 PIN을 요구합니다
Auto-lock after inactivity30분5 / 15 / 30 / 60분, 또는 안 함(탭이 닫힐 때까지)

둘 다 이미 열려 있는 세션을 포함해 동시에 적용됩니다. 공용이거나 신뢰할 수 없는
컴퓨터에서는 첫 번째 설정을 끄고 자리를 비울 때 지갑을 잠그십시오.

패스키로 잠금 해제하기

기기에 지문 인식기, Face ID, Windows Hello 또는 보안 키가 있다면 PIN을 입력하는 대신
그것으로 잠금을 해제할 수 있습니다.

Settings → 🔑 Security → Passkey Unlock → Enable passkey unlock에서 켭니다. 기기가
등록을 요청합니다 — 두 번 요청할 수 있는데, 한 번은 패스키 생성, 한 번은 사용을 위한 것입니다.
그러면 잠금 해제 화면의 PIN 입력란 위에 👆 Unlock with passkey가 표시됩니다.

알아 두어야 할 사항:

  • PIN은 여전히 존재하며 여전히 중요합니다. 패스키는 지갑을 여는 것이지 PIN을 대체하는 것이
    아닙니다. 키 내보내기, 복구 문구 표시, PIN 변경, 새 계정 파생은 모두 여전히 PIN을 요구합니다. PIN을
    잊지 마십시오 — PIN 분실은 패스키가 있어도 해결되지 않습니다.
  • 패스키는 이 기기와 이 브라우저에 묶여 있습니다. 패스키는 지갑 데이터와 함께 이동하지
    않습니다. 다른 기기에서는 PIN으로 잠금을 해제하고, 원한다면 거기서 패스키를 등록하십시오.
  • 귀하의 지문은 지갑에 도달하지 않습니다. 기기가 로컬에서 귀하를 확인하고, 패스키에서 파생된
    비밀을 페이지에 전달합니다. 그 비밀이 지갑을 여는 열쇠입니다.
  • 사용 가능 여부는 기기와 브라우저에 따라 다릅니다. 기기가 필요한 기능을 수행할 수 없다면
    Security 패널이 그 사실을 알리고 옵션은 꺼진 상태로 유지됩니다 — PIN은 이전과 똑같이 작동합니다.
  • 같은 패널에서 패스키 잠금 해제를 끌 수 있습니다. 그러면 저장된 사본이 즉시 삭제되지만,
    기기에서 패스키 자체가 삭제되지는 않으며 OS나 브라우저 설정에서 제거할 수 있습니다.

패스키가 더 이상 지갑을 열지 못하게 되면 — 회전되거나 다시 등록된 자격 증명, 또는 복원된 기기 —
지갑은 그 사실을 알리고 오래된 사본을 폐기한 다음 PIN을 요구합니다. 잃는 것은 없으며,
이후 새 패스키를 등록할 수 있습니다.

조회 전용 계정이 활성화된 동안에는 패스키 잠금 해제를 등록할 수 없습니다. 키가 없으므로
패스키로 봉인할 대상이 없기 때문입니다. Security 패널이 버튼 대신 그 사실을 알려줍니다.

세션 만료

동일한 시간 창이 dApp 연결에도 적용되며, 연결은 자동으로 만료됩니다.

  • 유휴 시간 제한: 30분간 비활성
  • 절대 시간 제한: 연결 후 8시간

세션이 만료되면 지갑이 연결을 닫고 dApp에 통보합니다.
그러면 dApp이 재연결을 요청해야 합니다.

세션이 만료되면 어떤 일이 벌어지나

  1. 지갑이 dApp에 sessionExpired 이벤트를 발생시킵니다.
  2. dApp이 만료된 세션을 감지하고 "Reconnect" 프롬프트를 표시합니다.
  3. Connect를 클릭하여 지갑 팝업을 다시 엽니다.
  4. 지갑이 세션을 복원하고 dApp이 계속 작동합니다.

dApp이 자동으로 재연결되지 않는 경우

  • dApp에서 Connect 버튼을 클릭합니다.
  • 지갑 팝업이 열리면 연결을 승인합니다.
  • 이전 세션 데이터는 보존되므로 지갑을 다시 가져올 필요가 없습니다.

네트워크 설정

Settings → ⚙️ General에는 지갑이 통신하는 RPC URL, 링크 대상 탐색기(explorer),
그리고 선택적인 프록시가 있습니다. RPC URL을 변경하고 Save URLs를 선택하면 지갑이
다른 노드를 가리키게 됩니다.

자체 네트워크 추가

Devnet과 Mainnet은 지갑에 포함되어 있습니다. 다른 네트워크를 추가하려면 — 귀하의 노드, devnet 포크,
유료 RPC — 같은 패널에서 Custom Networks로 스크롤한 뒤 다음을 입력합니다.

필드필수참고
Network name예dApp을 포함해 네트워크가 표시되는 모든 곳에 나타납니다
RPC URL예http:// 또는 https://
Explorer URL아니요기본값은 RPC URL입니다
Relayer URL아니요스텔스 전송에만 필요합니다

Add network를 선택하면 목록에 추가됩니다. 그때부터 일반적인 선택지가 됩니다.

  • 상단 바의 network pill로 다른 프리셋처럼 전환할 수 있고,
  • 사이트가 연결을 요청하면 connect popup에 (custom) 표시로 나열되며,
  • 연결된 dApp은 그 이름과 탐색기를 읽어 올바르게 라벨을 표시할 수 있습니다.

네트워크 전환은 RPC, 탐색기, 릴레이어의 세 엔드포인트를 모두 함께 갱신하므로,
지갑이 한 네트워크를 읽으면서 다른 네트워크로 링크하는 일이 생기지 않습니다.

네트워크 옆의 ✕로 제거할 수 있습니다. 현재 사용 중인 네트워크를 삭제하면
지갑은 프리셋으로 대체합니다.

dApp이 보는 것. 귀하가 연결한 사이트는 커스텀 네트워크의 이름, 아이콘, 탐색기 URL, 그리고
귀하가 추가했다는 사실을 읽을 수 있습니다. 그러나 RPC나 릴레이어 URL은 읽을 수 없습니다 —
홈 노드의 주소나 제공자 키는 지갑에 남습니다. 이름은 보이므로,
네트워크 이름을 개인적인 것과 관련지어 짓지 마십시오.

HTTPS가 없는 노드

https:// 노드는 특별한 처리가 필요 없습니다. 그러나 일반 http://로만 접근할 수 있는 노드는
다른 문제입니다. 지갑이 노드에 요청하는 모든 것 — 모든 잔액·기록 조회, 제출하는 모든 거래 — 은
평문으로 전송되며, 네트워크 경로상의 누구든 그것을 읽고 답을 바꿀 수 있기 때문입니다.
그래서 지갑은 먼저 확인을 받습니다.

  • 루프백(loopback)은 권한이 필요 없습니다. localhost, 127.0.0.1, [::1] 등은
    귀하의 기기를 벗어나지 않으므로 로컬 노드는 바로 작동합니다.
  • 다른 http:// 주소는 명시적으로 신뢰해야 합니다. URL을 붙여넣으면 패널이 옆의
    Trust http://… 버튼과 함께 무엇이 문제인지 설명합니다. 신뢰는 출처별(스킴, 호스트, 포트)로
    저장되므로, 한 노드를 신뢰해도 다른 노드가 신뢰되지 않으며, 같은 호스트의 다른 포트는 별도의 결정입니다.
  • Trusted plaintext endpoints는 신뢰한 항목을 나열하며, Remove로
    되돌릴 수 있습니다.

풀 수 없는 두 가지 제한이 있으며, 패널은 방해가 되는 쪽이 어느 것인지 알려줍니다.

  • https://로 제공되는 지갑은 http://를 전혀 가져올 수 없습니다. 브라우저가 이를
    차단하며(혼합 콘텐츠), 출처를 신뢰해도 바뀌지 않습니다. 노드를 TLS 뒤에 두거나, 프록시를
    사용하거나, 일반 http 또는 localhost 빌드에서 지갑을 여십시오.
  • 배포된 빌드는 https://와 루프백만 허용합니다. 보안 정책은 빌드 시점에 고정되며
    실행 중에는 넓힐 수 없습니다. 일반 http가 필요한 자체 호스팅 사용자는
    VITE_ALLOW_HTTP_ENDPOINTS=1로 빌드할 수 있습니다. 위의 신뢰 목록은 여전히 그 위에 적용됩니다.

탐색기 URL은 이 모든 것에서 예외입니다. 그것은 단지 귀하가 클릭하는 링크일 뿐이며,
지갑이 가져오는 대상이 아닙니다.

RPC 프록시

RPC proxy (optional)는 호출을 귀하가 선택한 URL을 통해 라우팅합니다. RPC URL이
그것에 퍼센트 인코딩되어 추가되며, 브라우저는 프록시에만 연결합니다. 이는 TLS나 CORS 헤더가 없는
노드에 대한 실질적인 해결책이며, 브라우저가 연결하는 대상이 프록시이므로 위의 규칙을 충족합니다.

프록시는 지갑이 만드는 모든 요청을 보게 되므로 직접 운영하십시오. 프록시는 아무것도 서명하거나
귀하의 키에 닿을 수 없지만, 지켜볼 수 있고 거짓말을 할 수 있습니다.

무언가 잘못되었을 때

RPC 엔드포인트를 구성된 대로 사용할 수 없으면 헤더에 ⚠️ Insecure RPC가 나타납니다.
그것을 선택하면 해당 설정으로 바로 이동합니다. 네트워크 오류도 이유를 함께 전달하므로,
"Failed to fetch"만 표시되어도 무엇을 고쳐야 할지 알 수 있습니다.

백업 및 복구

내보내기

Settings → Backup → Export는 암호화된 .oct 파일을 다운로드합니다. 그것은
PIN으로 보호되지만 민감한 것으로 취급하십시오.

복원

Import → Wallet file을 사용하고 파일을 내보낼 당시 사용한 PIN을 입력하십시오.

여러 계정

Settings → Accounts는 같은 복구 문구에서 추가 계정을 파생합니다. 하나의
문구로 모든 계정이 복원됩니다.

복구 문구가 복원하지 못하는 두 가지가 있습니다. 그것들은 결코 문구에서 파생되지 않았기 때문입니다.

  • 조회 전용 계정 — 지갑에 추적을 요청한 주소일 뿐입니다. 재설치 후 되살리려면
    따로 적어 두십시오.
  • 연락처 — 중요하다면 Settings → Contacts에서 ⤓로 내보내십시오.

어느 쪽도 자금을 보유하지 않으므로, 잃어도 돈이 아닌 편의만 잃는 것입니다.

문제 해결

페이지가 비어 있거나 로딩에 멈춘 경우

새로고침하십시오. 계속되면 Retry 버튼이 있는 오류 카드가 나타나야 합니다.
표시된 메시지를 보고해 주십시오.

암호화 잔액을 사용할 수 없는 경우

Settings → PVAC에 다음 중 하나가 표시됩니다.

메시지의미해결책

수정을 적용한 후 ↻ Reload PVAC를 누르십시오 — 재시작은 필요 없습니다.

"Failed to load history" / 네트워크 오류

대개 RPC 노드에 연결할 수 없거나 CORS를 차단하고 있습니다. Settings에서 RPC URL을
확인하고, CORS 참고 사항을 보십시오. 오류가 이유를 명시한다면 —
평문, 혼합 콘텐츠, 또는 빌드 제한 — 네트워크 설정을
참조하십시오. CORS 경우는 RPC proxy로 해결됩니다.

헤더에 "⚠️ Insecure RPC"가 표시되는 경우

구성된 RPC 엔드포인트가 일반 http://이며 현재 상태로는 사용할 수 없습니다. 배지를
선택하여 설정을 열면 정확한 원인과 해결책이 설명되어 있습니다.
네트워크 설정을 참조하십시오.

📷 Scan 선택 시 카메라가 열리지 않는 경우

  • 브라우저가 요청할 때 카메라 권한을 허용하십시오. 닫아버렸다면 사이트 권한에서
    다시 허용하고 시도하십시오.
  • 카메라 접근에는 보안 페이지가 필요합니다. https://와 localhost에서는 작동하지만,
    다른 호스트의 일반 http:// 페이지에서는 작동하지 않습니다.
  • 다른 앱이 카메라를 사용 중이라면 먼저 닫으십시오. 대신 주소를 붙여넣어도 됩니다.

"Unlock with passkey"가 표시되지 않는 경우

이 브라우저에 등록된 패스키가 없거나, 기기가 패스키 잠금 해제에 필요한 기능을 수행할 수 없습니다.
Settings → 🔑 Security → Passkey Unlock에 그 이유가 표시됩니다. 패스키는 기기별·브라우저별이므로,
다른 곳에서 등록한 패스키는 여기에 나타나지 않습니다. PIN은 항상 작동합니다.

PIN을 잊어버린 경우

복구 문구를 사용하여 지갑을 다시 설치하고 새 PIN을 설정하십시오. 문구가 없으면
자금은 누구에게도 복구될 수 없습니다.

"Could not read your saved wallets" / "Could not read your accounts"

지갑이 로컬 데이터베이스를 열지 못했습니다. 삭제된 것은 없습니다. 이것은 거의
항상 다른 Orion 탭이나 남아 있는 Connect 팝업이 데이터베이스를 계속 잡고 있기 때문입니다.
업데이트 후에도 이전 탭이 데이터베이스에 붙어 있는 한 브라우저는 데이터베이스를 업그레이드하지 않습니다.

다른 Orion 탭과 팝업을 닫은 다음 ↻ Try again을 선택하십시오. 메시지가 계속되면
모든 Orion 탭을 닫고 지갑을 단일 탭에서 다시 여십시오.

잠금 해제 화면은 두 상태를 의도적으로 구분합니다. No stored wallet found는 데이터베이스가
정말 비어 있음을 의미하고, Could not read your saved wallets는 계정이 존재하지만
일시적으로 접근할 수 없음을 의미합니다. 두 번째 메시지가 보이는 동안에는
새 지갑을 만들지 마십시오.

업데이트 후 지갑이 사라진 경우

데이터는 첫 실행 시 이전 빌드에서 자동으로 마이그레이션됩니다. 계정이 없다면
새 지갑을 만들지 마십시오 — 이전 데이터를 덮어쓸 수 있습니다. 문제를 보고하고,
그동안 복구 문구로 복원하십시오.

dApp이 "Session expired"라고 표시하는 경우

지갑 세션이 시간 초과되었음을 의미합니다(유휴 30분 / 절대 8시간). dApp에서
Connect를 클릭하여 재연결하십시오. 지갑 데이터는 보존됩니다 — 연결만
다시 승인하면 됩니다.

자금을 안전하게 유지하기

권장 사항

  • 복구 문구를 오프라인, 종이에, 가능하면 여러 장소에 보관하십시오
  • 보내기 전에 수신자 주소를 검증하십시오
  • dApp 연결 프롬프트에 표시된 출처를 검증하십시오
  • 새 주소로 보낼 때는 소액의 테스트 거래부터 시작하십시오
  • 수취인을 연락처로 저장하고 이름을 확인하십시오 — 알아보는 이름이 base58을 읽는 것보다 낫습니다
  • 실제 계정을 잠금 해제하는 대신 조회 전용 계정으로 콜드 스토리지를 지켜보십시오

금지 사항

  • 어떤 웹사이트에도 복구 문구를 입력하지 마십시오. Orion Wallet은 설정 이후 절대 묻지 않습니다
  • 문구를 스크린샷, 암호 관리자 메모, 클라우드 드라이브 또는 채팅에 저장하지 마십시오
  • 개인 키나 .oct 파일을 공유하지 마십시오
  • 실제 자금이 담긴 지갑을 공용 또는 신뢰할 수 없는 컴퓨터에서 사용하지 마십시오

Orion Wallet은 독립적인 감사를 받지 않았습니다. 상당한 가치를 보관하기 전에
보안 문서를 검토하십시오.
