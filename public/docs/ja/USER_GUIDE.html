Orion Wallet — ユーザーガイド

Orion Wallet はすべてブラウザ内で動作します。鍵はローカルで生成され、PIN で暗号化されて
お使いの端末にのみ保存されます。サーバーには何も送信されません。

GitHub: github.com/maragung/OrionWallet — ソースコード、Issue、リリース。

はじめに

動作要件

  • Chrome、Edge、Firefox、Safari の最新版
  • JavaScript が有効であること
  • 暗号化残高機能を使う予定がある場合はおよそ 4 GB の RAM

起動方法

ホスティング済みのデプロイを利用するか、ローカルで実行します。

npm install --legacy-peer-deps
npm run dev

続いて <http://localhost:5173> を開きます。

ウォレットの作成

  1. Create New Wallet を選択し、アカウントに名前を付けて PIN を決めます。PIN はこの端末上のウォレットを暗号化します。
  2. リカバリーフレーズを書き留めてください。12 個の単語が表示されます。表示されたとおりの順序で紙に書き写します。
  3. I've Written It Down を選択します。するとウォレットは、フレーズが実際に画面から消えたことを確認するため、ランダムに選ばれた 3 個の単語の再入力を求めます。もう一度確認したいときは Show Phrase Again で再表示でき、誤って入力しても、やり直せるだけです。
  4. 単語の確認が済むと、ウォレットが開きます。
ウォレットを作成しただけでは開きません。単語の確認に通ることで開きます。それまでは
いつでも離れることができ、フレーズはまだ頼りにされていないため、失われるものは何もありません。
リカバリーフレーズは、ウォレットを復元する唯一の手段です。フレーズを持つ者は誰でも
あなたの資金を支配できます。オフラインで保管してください。決して写真に撮ったり、ウェブサイトに入力したり、
チャットやメールに貼り付けたりしないでください。

PIN とリカバリーフレーズの違い

リカバリーフレーズPIN
用途どこからでもウォレットを復元するこの端末上でのみロックを解除する
紛失した場合資金は復元不能リカバリーフレーズから復元する
保管場所あなた自身がオフラインで保存されない — あなただけが知っている

既存ウォレットのインポート

Import を選び、次のいずれかを選択します。

  • リカバリーフレーズ — 12/24 個の単語を入力します
  • 秘密鍵 — base64 形式の秘密鍵を貼り付けます
  • ウォレットファイル — 暗号化された .oct ファイルをアップロードし、その PIN を入力します

日常の使い方

残高の確認

Balance タブには公開残高が表示され、PVAC が有効な場合は暗号化残高も表示されます。

受け取り

Receive を開くと、あなたのアドレスと QR コードが表示されます。アドレスは公開情報であり、
共有しても安全です。

特定の金額を要求することもできます。その場合、QR コードにはアドレスと並んで金額も含まれ
（octra:<address>?amount=<OCT> の形式）、読み取ったウォレットは両方を自動入力します。
金額を要求しなければ、コードは単なるアドレスのままで、どのスキャナーでも読み取れます。

送金

  1. Send を開きます。
  2. 受取人を、都合のよい方法で指定します。
    • アドレスを貼り付けます（oct で始まります）。
    • 📇 Contacts… から保存済みの名前を選びます。
    • 📷 Scan を選ぶと、カメラで QR コードを読み取れます。初回はブラウザがカメラの許可を求めます。画像はページ内で処理され、アップロードされることは決してありません。金額を含むコードを読み取れば、金額も入力されます。
  3. 金額を入力します。
  4. 手数料とノンスを確認し、PIN で承認します。

アドレスが保存済みの連絡先と一致すると、フォームはその隣に名前を表示します。見覚えのある名前は
base58 の文字列よりもはるかに確実な確認手段です。新しいアドレスなら、＋ Save to contacts
で任意のラベルを付けて保存でき、次回の支払いは貼り付けではなく選択で済みます。

承認する前に、必ず受取アドレスの最初と最後の文字を確認してください。
取引を取り消すことはできません。

履歴

History には最近の取引が一覧表示されます。ネットワークに到達できない場合は、キャッシュされた項目が
表示され、⚠ Cached と印が付きます。

⤓ はテーブルを CSV ファイル（時刻、ハッシュ、種別、送信元、送信先、方向、金額、手数料、
ステータス）に書き出し、表計算ソフトやご自身の記録に利用できます。書き出されるのは現在読み込まれている行
です — 見えているものがそのまま出力されます — ので、より広い範囲が必要なら先に Load more を使ってください。
ファイルはブラウザによってダウンロードフォルダに書き込まれ、どこにも送信されません。

連絡先（アドレス帳）

Settings → 📇 Contacts は、任意の名前を付けたアドレスの一覧を保持します。各項目には
アドレス、名前、そして任意のメモがあり、メモは「memo required」や、入金アドレスがどの取引所の
ものかといった情報を書くのに適しています。

意義: 読めないアドレスは、確認できないアドレスです。受取人を一度保存しておけば、Send フォームは
その人を名前で提示し、貼り付け直したアドレスにも名前を表示するので、すり替えられたり切り詰められたりした
アドレスは、紛れ込むのではなく目立つようになります。

  • ここで項目を Add するか、Send フォームから直接 ＋ Save to contacts を使います。
  • ✎ は項目の名前を変更し、🗑 は削除します。連絡先を削除しても、オンチェーンには何の影響もありません。
  • ⤓ は一覧を CSV として書き出すので、他の記録と一緒に保管したり、別のブラウザへ移したりできます。

連絡先はこのブラウザ内にのみ、他のウォレットデータと並んで保存されます。アップロードされることはなく、
ウォレットを消去すると他のすべてと一緒に消去されます。

ウォッチ専用アカウント

ウォッチ専用アカウントは、あなたが鍵を持っていないアドレスを追跡します — コールドストレージ、
ハードウェアウォレット、取引所の入金アドレス、見守りたい他人のアドレスなどです。

Settings → 👥 Accounts → 👁 Watch Address から追加します。アドレスを貼り付け、名前を付ければ、
アカウント一覧に加わります。

できること: 残高の表示、履歴の一覧、CSV の書き出し、そして PIN なしでの切り替え — 復号すべき
キーストアがないので、ロックを解除するものが何もないのです。

できないこと: 署名すること。送金、暗号化/復号、ステルス送金、コントラクト呼び出し、dApp の署名要求は
すべて拒否され、Send フォームは入力後ではなく入力前にその旨を伝えます。ウォッチ専用アカウントは
アカウント一覧とヘッダーで 👁 と印が付くので、どちらの種類を見ているかが常に分かります。

ウォッチ専用アカウントを本物のアカウントにするには、そのアドレスのリカバリーフレーズか秘密鍵を
インポートします。鍵を追加することが唯一の方法で、近道はありません。

暗号化残高（FHE）

Orion Wallet は残高の一部を完全準同型暗号（FHE）を使って暗号化した状態で保持でき、
金額がオンチェーンで公開表示されないようにできます。

これは任意です。有効にしていてもいなくても、その他すべては動作します。

有効化する

Settings → PVAC に移動します。2 つのインジケーターが両方とも緑になっている必要があります。

  • WASM Module — 暗号モジュールが読み込まれた
  • Bridge Initialized — ウォレットのシードから鍵が生成された

いずれかが準備できていない場合、パネルが正確な原因と対処法を説明します。

暗号化と復号

Encrypt を使って、公開残高と暗号化残高の間で資金を移動します。これらの操作は
計算負荷が高く、数秒かかることがあります。進捗ダイアログが各段階を表示します。

ステルス送金

ステルス送金は、受取人の公開鍵から導出した使い捨てアドレスへ資金を送るため、
その支払いが受取人のメインアドレスと公開の場で結び付けられません。

Stealth を開き、受取人と金額を入力して承認します。受取人は自分の Stealth タブから
資金を受け取ります。

dApp への接続

ウェブサイトが接続を要求すると、要求元のオリジンを示すポップアップが表示されます。

承認する前に:

  • オリジンを注意深く確認してください。ドメインが意図したサイトと正確に一致することを確かめます。
  • 想定どおりの権限のみを承認します。
  • 「Trust this site」は読み取り専用の要求について今後の確認を省略します — 控えめに使ってください。
  • ポップアップのネットワークセレクターを確認します。自分で追加したものも含め、保有するすべてのネットワークが一覧表示されるので、ポップアップを離れずに正しいネットワークで接続できます。

接続はいつでも Settings → Connected Sites で確認・取り消しができます。

ロックとロック解除

PIN はウォレットを復号します。復号された鍵はロック解除セッションが続く間ずっと利用可能な状態で保たれ、
セッションが終わるまで PIN を再度求められることはありません。

  • ページを再読み込みしてもロック解除は維持されます。鍵は今いるブラウザタブ向けに再封印されるので、再読み込みしても PIN 画面に戻ることなくセッションが引き継がれます。その間、一瞬だけ「Restoring your session…」と表示されます。
  • タブを閉じるとセッションは終了します。封印されたコピーはその 1 つのタブに限定されており、タブとともに消えるため、新しいタブやウィンドウはロックされた状態で始まります。
  • ヘッダーの 🔒 は即座にロックし、封印されたコピーを破棄します — ロック後に再読み込みすると、当然ながら PIN を求められます。
  • 無操作が続くとウォレットはロックされます。既定では 30 分後で、1 回のロック解除は活動の有無にかかわらず 8 時間を超えて持ち越されることはありません。

封印されたセッションは、どちらの半分だけでも役に立ちません。暗号化された鍵はタブが保持し、
それを開く鍵はブラウザが、どのページ — このページ自身を含め — も読み出せない形で保持します。

Settings → Security → Session & Auto-Lock では:

設定既定値動作
Stay unlocked after a page refreshオンオフにすると、再読み込みのたびに PIN が必要になります
Auto-lock after inactivity30 分5 / 15 / 30 / 60 分、または無効（タブを閉じるまで）

両方が同時に適用され、すでに開いているセッションにも適用されます。共有の、あるいは信頼できない
コンピューターでは、前者をオフにし、離席するときはウォレットをロックしてください。

パスキーでのロック解除

お使いの端末に指紋リーダー、Face ID、Windows Hello、またはセキュリティキーがあれば、PIN を入力する
代わりにそれでロックを解除できます。

Settings → 🔑 Security → Passkey Unlock → Enable passkey unlock でオンにします。端末が登録を
求めます — パスキーを作成するときと使用するときの2 回求められることがあります。その後、ロック解除画面には
PIN 入力欄の上に 👆 Unlock with passkey が表示されます。

知っておくとよいこと:

  • PIN は依然として存在し、依然として重要です。パスキーはウォレットを開きますが、PIN を置き換えるものではありません。鍵のエクスポート、リカバリーフレーズの表示、PIN の変更、新しいアカウントの導出は、いずれも引き続き PIN を求めます。PIN は保持してください — 紛失してもパスキーがあれば解決するわけではありません。
  • この端末とこのブラウザに紐付いています。パスキーはウォレットデータとともに移動しません。別の端末では PIN でロックを解除し、必要ならそこでパスキーを登録してください。
  • あなたの指紋がウォレットに届くことはありません。端末はローカルであなたを検証し、パスキーから導出した秘密をページに渡します。ウォレットを開くのはその秘密です。
  • 利用可否は端末とブラウザに依存します。お使いの環境がこの機能に必要なことを行えない場合、Security パネルがその旨を伝え、オプションはオフのままになります — PIN はこれまでどおり正確に機能し続けます。
  • パスキーによるロック解除をオフにするには、同じパネルで行います。それにより保存されたコピーは即座に削除されます。端末からパスキー自体が削除されるわけではなく、そちらは OS やブラウザの設定で削除できます。

パスキーがウォレットを開けなくなった場合 — 更新・再登録された資格情報や、復元された端末など — ウォレットは
その旨を伝え、古くなったコピーを破棄して PIN を求めます。失われるものは何もなく、後で新しいパスキーを
登録できます。

ウォッチ専用アカウントがアクティブな間は、パスキーによるロック解除を登録できません — 鍵を保持していないので、
パスキーが封印すべきものがないのです。Security パネルはボタンの代わりにその旨を表示します。

セッションの有効期限

同じ制限時間が dApp 接続にも適用され、接続は自動的に期限切れになります。

  • アイドルタイムアウト: 無操作が 30 分
  • 絶対タイムアウト: 接続から 8 時間

セッションが期限切れになると、ウォレットは接続を閉じ、dApp に通知します。
その後、dApp は再接続を促すはずです。

セッションが期限切れになると何が起きるか

  1. ウォレットが dApp に sessionExpired イベントを送出します。
  2. dApp が期限切れのセッションを検出し、「Reconnect」の案内を表示します。
  3. Connect をクリックすると、ウォレットのポップアップが再び開きます。
  4. ウォレットがセッションを復元し、dApp が再開します。

dApp が自動的に再接続しない場合

  • dApp の Connect ボタンをクリックします。
  • ウォレットのポップアップが開きます — 接続を承認します。
  • 以前のセッションデータは保持されているので、ウォレットを再インポートする必要はありません。

ネットワーク設定

Settings → ⚙️ General には、ウォレットが通信する RPC URL、リンク先のエクスプローラー、および
任意のプロキシが保持されます。RPC URL を変更して Save URLs を選ぶと、ウォレットを別のノードに
向けられます。

独自ネットワークの追加

Devnet と Mainnet はウォレットに同梱されています。別のもの — 自分のノード、devnet のフォーク、
有料 RPC — を追加するには、同じパネルの Custom Networks までスクロールし、次を入力します。

項目必須備考
Network nameはいdApp を含め、ネットワークが表示されるあらゆる場所に表示されます
RPC URLはいhttp:// または https://
Explorer URLいいえ既定では RPC URL になります
Relayer URLいいえステルス送金にのみ必要です

Add network を選ぶと一覧に加わります。それ以降は通常の選択肢になります。

  • 上部バーのネットワークピルが、他のプリセットと同様にそれへ切り替わります。
  • 接続ポップアップは、サイトが接続を求めるときにそれを (custom) と印を付けて一覧に表示します。
  • そして接続中の dApp はその名前とエクスプローラーを読み取れるので、表示を正しくラベル付けできます。

ネットワークを切り替えると、3 つのエンドポイント — RPC、エクスプローラー、リレイヤー — がまとめて
更新されるので、ウォレットが一方のネットワークを読みながら別のネットワークにリンクする状態には決してなりません。

ネットワークはその横の ✕ で削除します。現在使用中のものを削除した場合、ウォレットは
プリセットにフォールバックします。

dApp から見えるもの。接続先のサイトは、カスタムネットワークの名前、アイコン、エクスプローラー
URL、そしてあなたが追加したという事実を読み取れます。その RPC やリレイヤーの URL は読み取れません — 自宅
ノードのアドレスやプロバイダーのキーはウォレット内にとどまります。名前は見えるので、ネットワークに
個人的なものにちなんだ名前を付けるのは避けてください。

HTTPS を使わないノード

https:// のノードには特別な対応は不要です。プレーンな http:// でのみ到達できるノードは
別問題です。ウォレットがそのノードに尋ねること — あらゆる残高・履歴の照会、送信するすべての取引 — が
平文で流れ、経路上の誰もがそれを読み取り、答えを書き換えることさえできるからです。そのため、
ウォレットはまず尋ねます。

  • ループバックには許可は不要です。localhost、127.0.0.1、[::1] などは決してマシンの外に出ないので、ローカルノードはそのまま動作します。
  • それ以外の http:// アドレスは明示的に信頼する必要があります。URL を貼り付けると、パネルが隣の Trust http://… ボタンとともに何が問題になるかを説明します。信頼はオリジン単位（スキーム、ホスト、ポート）で保存されるので、あるノードを信頼しても別のノードは信頼されず、同じホストの別ポートは別の判断になります。
  • Trusted plaintext endpoints には信頼済みのものが一覧表示され、Remove で取り消せます。

私たちには解除できない制限が 2 つあり、パネルはそのうち妨げになっている方を示します。

  • https:// で配信されたウォレットは、http:// をまったく取得できません。ブラウザがそれをブロックし（混在コンテンツと呼ばれます）、オリジンを信頼しても変わりません。ノードを TLS の背後に置くか、プロキシを使うか、プレーン http もしくは localhost のビルドからウォレットを開いてください。
  • 同梱のビルドは https:// とループバックのみを許可します。そのセキュリティポリシーはビルド時に固定されており、実行中に緩めることはできません。プレーン http が必要な自己ホスト運用者は VITE_ALLOW_HTTP_ENDPOINTS=1 でビルドできますが、その上でも上記の信頼リストは適用されます。

エクスプローラー URL はこれらすべての対象外です — それはクリックするリンクにすぎず、ウォレットが
取得するものではないからです。

RPC プロキシ

RPC proxy (optional) は、お好みの URL を経由して呼び出しをルーティングします。RPC URL が
パーセントエンコードされてそれに付加され、ブラウザは常にプロキシにのみ接続します。これは TLS も CORS
ヘッダーも持たないノードに対する実用的な解決策であり、ブラウザが行う接続先はプロキシなので、上記の規則も
満たします。

プロキシはウォレットが行うすべての要求を見るので、自分で運用してください。プロキシは何にも署名
できず、鍵にも到達できませんが、監視することはでき、嘘をつくこともできます。

何かおかしいとき

RPC エンドポイントを設定どおりに使えない場合、ヘッダーに ⚠️ Insecure RPC が表示されます。
それを選ぶと、その設定へ直接移動します。ネットワークエラーにも理由が付くので、素っ気ない
「Failed to fetch」だけでなく、何を直せばよいかが分かります。

バックアップと復元

エクスポート

Settings → Backup → Export は暗号化された .oct ファイルをダウンロードします。
PIN で保護されていますが、機密情報として扱ってください。

復元

Import → Wallet file を使い、そのファイルをエクスポートしたときに使っていた PIN を入力します。

複数アカウント

Settings → Accounts は、同じリカバリーフレーズから追加のアカウントを導出します。
1 つのフレーズでそれらすべてを復元できます。

フレーズが復元しないものが 2 つあります。もともとフレーズから導出されていないからです。

  • ウォッチ専用アカウント — これらは単に、ウォレットに追跡を依頼したアドレスにすぎません。再インストール後に取り戻したい場合は、別途書き留めておいてください。
  • 連絡先 — 大切なら、Settings → Contacts で ⤓ を使ってエクスポートしてください。

どちらも資金を保持していないので、失っても失うのは利便性であって、お金ではありません。

トラブルシューティング

ページが真っ白、または読み込みで止まる

再読み込みしてください。それでも続く場合は、Retry ボタンの付いたエラーカードが表示されるはずです。
そこに表示されるメッセージを報告してください。

暗号化残高が利用できない

Settings → PVAC には次のいずれかが表示されます。

メッセージ意味対処
The WASM module has not been compiledpvac.js が配信されていないnpm run build:wasm を実行する
Content-Security-Policy is blocking WebAssemblyCSP に 'wasm-unsafe-eval' が欠けているindex.html の script-src に追加する
The compiled module is out of dateビルドが必要な関数より古いnpm run build:wasm で再ビルドする
FHE key generation failedモジュールは読み込まれたが鍵生成に失敗したブラウザのコンソールを確認し報告する

対処を適用したら ↻ Reload PVAC を押してください — 再起動は不要です。

「Failed to load history」／ネットワークエラー

たいていは RPC ノードに到達できないか、CORS をブロックしています。Settings で RPC URL を
確認し、CORS に関する注記を参照してください。エラーに理由が示されている場合 —
平文、混在コンテンツ、またはビルドの制限 — は、ネットワーク設定を参照してください。
CORS のケースは RPC proxy で解決できます。

ヘッダーに「⚠️ Insecure RPC」と表示される

設定された RPC エンドポイントがプレーンな http:// で、そのままでは使用できません。バッジを選ぶと
その設定が開き、正確な原因と対処法が詳しく示されます。ネットワーク設定を
参照してください。

📷 Scan を選んでもカメラが開かない

  • ブラウザが尋ねてきたらカメラの許可を与えてください。却下してしまった場合は、サイトの権限設定で再度許可し、もう一度試します。
  • カメラへのアクセスには安全なページが必要です。https:// と localhost では動作しますが、別ホスト上のプレーンな http:// ページでは動作しません。
  • 別のアプリがカメラを占有している場合は、先にそれを閉じてください。いつでも代わりにアドレスを貼り付けることもできます。

「Unlock with passkey」が表示されない

このブラウザにパスキーが登録されていないか、端末がパスキーによるロック解除に必要なことを行えないかの
いずれかです。Settings → 🔑 Security → Passkey Unlock がどちらかを示します。パスキーは端末ごと・
ブラウザごとなので、別の場所で登録したものはここには表示されません。PIN は常に機能します。

PIN を忘れた

リカバリーフレーズを使ってウォレットを再インストールし、新しい PIN を設定してください。フレーズがなければ、
資金は誰にも復元できません。

「Could not read your saved wallets」／「Could not read your accounts」

ウォレットがローカルデータベースを開けませんでした。何も削除されていません — これはほぼ必ず、別の Orion
タブか、閉じ残った Connect ポップアップがデータベースを開いたまま保持していることが原因です。
更新後、古いタブがまだ接続している間は、ブラウザはデータベースをアップグレードしません。

他の Orion タブとポップアップを閉じてから、↻ Try again を選んでください。メッセージが消えない場合は、
すべての Orion タブを閉じ、1 つのタブでウォレットを開き直してください。

ロック解除画面は 2 つの状態を意図的に区別します。No stored wallet found はデータベースが本当に空で
あることを意味し、Could not read your saved wallets はアカウントは存在するが一時的に到達できないことを
意味します。2 つ目のメッセージが出ている間は、新しいウォレットを作成しないでください。

更新後にウォレットが消えた

データは初回起動時に古いビルドから自動的に移行されます。アカウントが見当たらない場合は、新しいウォレットを
作成しないでください — 古いデータを上書きしてしまうおそれがあります。この問題を報告し、その間は
リカバリーフレーズから復元してください。

dApp に「Session expired」と表示される

これはウォレットのセッションがタイムアウトした（30 分アイドル／8 時間絶対）ことを意味します。dApp の
Connect をクリックして再接続してください。ウォレットのデータは保持されており、接続を承認し直すだけで済みます。

資金を安全に保つには

すべきこと

  • リカバリーフレーズをオフラインで、紙に、できれば複数の場所に保管する
  • 送金前に受取アドレスを確認する
  • dApp の接続確認に表示されるオリジンを確認する
  • 新しいアドレスに送るときは、まず少額のテスト取引から始める
  • 受取人を連絡先に保存し、名前を確認する — 見覚えのある名前は base58 を読むよりも確実
  • 本物のアカウントのロックを解除する代わりに、ウォッチ専用アカウントでコールドストレージを見守る

決してしないこと

  • リカバリーフレーズをどのウェブサイトにも入力する。Orion Wallet はセットアップ後にそれを尋ねることは決してありません
  • フレーズをスクリーンショット、パスワードマネージャーのメモ、クラウドドライブ、チャットに保存する
  • 秘密鍵や .oct ファイルを共有する
  • 実際の資金を保持するウォレットを、共有または信頼できないコンピューターで使う

Orion Wallet は独立した監査を受けていません。相応の価値を保管する前に、
セキュリティドキュメントをご確認ください。
